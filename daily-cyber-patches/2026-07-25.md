Mode: Public defensive guidance. No private environment data included.

## Executive Summary

- CISA's live Known Exploited Vulnerabilities catalog is version 2026.07.24. Check Point SmartConsole CVE-2026-16232 and Microsoft SharePoint CVE-2026-50522 reach their remediation deadlines today. Confirm the products are absent, fixed, mitigated, or isolated, and perform vendor-directed incident triage where exposure existed.

Treat any installation or execution as an incident-assessment trigger; removal alone is not evidence that the host or reachable credentials are safe. - Package installation, import-time or CLI execution, CI jobs, editor activation, MCP startup, and agent tool calls are one connected developer-runtime boundary. Review delayed activation paths and separate untrusted content from credentials, publication, deployment, and durable memory.
- AI is shortening attacker research and operational cycles. Defenders should shorten inventory-to-remediation time while keeping deterministic authorization, sandboxing, scoped identities, and human approval around consequential actions.

## Copy/Paste Assessment

Run only the checks that match an environment you are authorized to review. These commands list filenames, package references, workflow settings, or executable names; they are not intended to print secret values.

```bash
# Set this placeholder to the workspace you are authorized to assess.
export WORKSPACE_ROOT="<WORKSPACE_ROOT>"
cd "$WORKSPACE_ROOT"
```

```bash
# Locate dependency manifests, lockfiles, registry configuration, native-build metadata,
# Python startup hooks, and editor or agent configuration without reading credential values.
find "$WORKSPACE_ROOT" -type f \( \
  -name package.json -o -name package-lock.json -o -name npm-shrinkwrap.json -o \
  -name pnpm-lock.yaml -o -name yarn.lock -o -name requirements.txt -o \
  -name pyproject.toml -o -name pylock.toml -o -name uv.lock -o \
  -name poetry.lock -o -name binding.gyp -o -name extconf.rb -o \
  -name '*.pth' -o -name .npmrc -o -name .pypirc -o \
  -name extensions.json -o -name mcp.json -o -name settings.json -o \
  -name tasks.json -o -name hooks.json \
\) -not -path '*/node_modules/*' -not -path '*/.venv/*' -print
```

```bash
# Review the four newly published npm identities in manifests and lockfiles.
# A match is an assessment trigger; do not install, import, restore, or execute it.
rg -n '(^|["/ ])(app-data-lts|app-data-layer|app-data-ist|app-node-layer)(["/@ <]|$)' \
  -g 'package.json' -g 'package-lock.json' -g 'npm-shrinkwrap.json' \
  -g 'pnpm-lock.yaml' -g 'yarn.lock' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Review declared lifecycle hooks. Their absence does not prove runtime safety.
rg -n '"(preinstall|install|postinstall|prepare)"[[:space:]]*:' \
  -g 'package.json' -g '!**/node_modules/**' "$WORKSPACE_ROOT" || true

# List registry configuration files that require authorized manual review.
# Do not print their contents in logs, issues, pull requests, or chat.
find "$WORKSPACE_ROOT" -type f \( -name .npmrc -o -name .pypirc \) \
  -not -path '*/node_modules/*' -not -path '*/.venv/*' -print
```

```bash
# Review workflow triggers, privileges, cache/artifact handoffs, runners, and action references.
if [ -d "$WORKSPACE_ROOT/.github/workflows" ]; then
  rg -n 'pull_request_target|workflow_run|issue_comment|id-token:[[:space:]]*write|contents:[[:space:]]*write|packages:[[:space:]]*write|permissions:|runs-on:[[:space:]]*self-hosted|actions/(checkout|cache|upload-artifact|download-artifact)@|uses:' \
    "$WORKSPACE_ROOT/.github/workflows" || true
fi
```


Assessment cautions:

- Do not infer one actor, one campaign, exposure, execution, or equivalent severity from advisory counts or similar package names.
- Do not investigate suspected malware by installing, importing, restoring, or executing it on a normal workstation.
- An install-script block does not stop registry configuration processing, native builds, package imports, CLIs, tests, plugins, editor activation, MCP startup, agent tools, or later execution.
- Verify affected product versions through vendor-supported inventory. Do not probe systems you do not own or administer.

## Copy/Paste Remediation

For a Node project with a reviewed lockfile and no evidence of compromise:

```bash
# Rebuild from the reviewed lockfile while suppressing lifecycle scripts during initial inspection.
npm ci --ignore-scripts
npm audit --audit-level=high
npm test
```

Package and registry controls:

- Prefer a default-deny model for dependency scripts, native builds, Git dependencies, remote dependencies, plugins, and executable package entry points. Approve only what the build requires.
- Use a routine release cooldown so brand-new package versions do not enter production immediately. Keep urgent security updates on a separately reviewed path.
- Pin direct and transitive dependencies with reviewed lockfiles and hashes where supported. Treat provenance as origin evidence, not proof that the source, workflow, or artifact is safe.
- Prefer short-lived trusted publishing over long-lived registry tokens. Protect the workflow, environment, branch, repository identity, and human approval that can invoke the publisher.
- Treat publisher, ownership, registry host, resolved file set, old-version file additions, permissions, dependencies, and runtime behavior changes as security-review events.

If a malicious package or extension was installed, imported, restored, or executed:

1. Stop using the affected environment for credentialed development, builds, releases, and deployments.
2. Isolate the environment and preserve relevant endpoint, process, editor, package-manager, CI, source-control, registry, identity, and signing logs under the incident-response policy.
3. Rebuild the workstation or runner from a known-good image rather than trusting package or extension removal alone.
4. Restore reviewed lockfiles, extensions, MCP servers, agent tools, workspace configuration, and startup configuration from known-good sources.
5. Rotate credentials reachable from the affected process through the relevant account, cloud, registry, signing, or secret-manager interface. Revoke active sessions and review audit logs.
6. Rebuild and compare release artifacts from reviewed source before restoring publication or deployment access.

For GitHub Actions, OIDC, caches, and runners:

```yaml
# Start every workflow with no token permissions; grant only what each job requires.
permissions: {}
```

- Never execute untrusted pull-request code in a privileged `pull_request_target`, `workflow_run`, comment-triggered, release, or publication job.
- Separate repository writes, `id-token: write`, cache writes, artifact promotion, signing, and publication into minimal reviewed jobs.
- Pin third-party actions to reviewed full commit SHAs and use dependency tooling to keep those pins current.
- Protect every branch, tag, environment, and reusable workflow that can publish or deploy. Require review for production environments.
- Validate immutable owner and repository IDs, audience, branch, environment, and reusable-workflow conditions in cloud trust policies. Remove obsolete name-only subjects after a verified migration.
- Use ephemeral isolated runners for untrusted code. Update runner binaries, base images, bootstrap automation, and cached templates together.
- Treat caches and artifacts crossing trust levels as untrusted inputs. Verify their origin and content before privileged consumption.

For MCP, agents, and editor extensions:

- Deny new packages, servers, tools, extensions, endpoints, and permissions by default. Approve the exact publisher, repository, version, endpoint, metadata, and capability.
- Treat tool descriptions, schemas, returned content, package documentation, retrieved files, issue text, web pages, code comments, workspace rules, and durable memory as untrusted data, never authorization.
- Open unfamiliar workspaces in Restricted Mode. Review tasks, settings, extension recommendations, MCP configuration, hooks, and executable paths before granting trust.
- Revoke approval whenever ownership, binary, dependencies, endpoint, tool description, schema, or requested permissions change.
- Bind each agent or MCP server to a dedicated least-privilege identity and narrow network destinations. For local servers, prefer sandboxed standard-input/output transport.
- Require human approval for credential use, external writes, publication, deployment, destructive actions, and scope expansion.
- Validate OAuth token issuer, audience, resource, scope, expiry, and client consent. Do not pass tokens through to downstream services.
- Authenticate local control planes, validate browser origins, bind network services to the narrowest interface, and isolate browsing or untrusted content from privileged tool execution.

For exploited products:

- Follow CISA-required actions and current vendor advisories. Patch supported systems, isolate unsupported or unmitigated systems, and discontinue products that cannot be secured.
- Treat Check Point SmartConsole CVE-2026-16232 and Microsoft SharePoint CVE-2026-50522 as due today, July 25.
- Apply the exact Check Point hotfix and access restrictions for the deployed release. Apply the correct Microsoft update for each supported on-premises SharePoint edition.
- Investigate relevant authentication, administrative, application, endpoint, and network activity where exposure existed. Patching closes the vulnerability but does not erase prior exploitation.

Verify operationally:

- A clean ephemeral CI run succeeds from the reviewed commit using reviewed lockfiles, pinned actions, and a current runner image.
- A staged release requires the intended protected branch, workflow, immutable identity, and approval; an unauthorized source cannot publish.
- Cloud federation succeeds only for the intended immutable GitHub subject and audience; a deliberately unauthorized request is denied.
- Package-registry, GitHub, cloud, identity, and signing logs show no unexplained actions after containment and credential rotation.
- MCP and agent tests demonstrate that untrusted content cannot add tools, change permissions, alter durable memory without review, reach privileged control planes, or trigger external writes without approval.
- Editor inventory matches the approved publisher and version list, and unfamiliar repositories remain restricted until configuration review is complete.
- Product owners record remediated version, deployment date, exposure review, and incident-triage result for every applicable KEV item.
