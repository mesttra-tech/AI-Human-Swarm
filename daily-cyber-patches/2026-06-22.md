# Daily Cyber Patch - 2026-06-22

Mode: Public defensive guidance. No private environment data included.

## Executive Summary

- The live CISA KEV catalog is still version 2026.06.18. Splunk Enterprise CVE-2026-20253 is now overdue, BerriAI LiteLLM CVE-2026-42271 is due today, and Cisco, Arista, and Chromium KEV entries are due tomorrow, 2026-06-23.
- Current public reporting continues to converge on developer-infrastructure compromise: npm lifecycle scripts, PyPI import-time execution, IDE plugins, AI-agent package ecosystems, and CI runners are all credential-exposure surfaces.
- Treat AI-assisted automation as a privileged workflow boundary. Issue text, PR text, agent prompts, MCP tool metadata, editor settings, package metadata, and registry provenance should not reach privileged tools without review, scoping, and logging.

## Copy/Paste Assessment

Run only the checks that match your environment. These commands should not print secret values.

```bash
# Set this to your local workspace before running checks.
export WORKSPACE_ROOT="<WORKSPACE_ROOT>"
cd "$WORKSPACE_ROOT"
```

```bash
# Pull current CISA KEV data for patch prioritization.
curl -fsSL https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json -o kev.json
jq -r '.catalogVersion, .dateReleased, (.vulnerabilities | sort_by(.dateAdded) | reverse | .[] | select(.dateAdded >= "2026-06-01") | [.dateAdded,.dueDate,.cveID,.vendorProject,.product,.knownRansomwareCampaignUse] | @tsv)' kev.json
```

```bash
# Find common Node and Python manifests and lockfiles.
find "$WORKSPACE_ROOT" -type f \( \
  -name package.json -o \
  -name package-lock.json -o \
  -name npm-shrinkwrap.json -o \
  -name pnpm-lock.yaml -o \
  -name yarn.lock -o \
  -name requirements.txt -o \
  -name pyproject.toml -o \
  -name pylock.toml -o \
  -name uv.lock \
\) -not -path '*/node_modules/*' -not -path '*/.venv/*' -print
```

```bash
# Review package lifecycle scripts without executing them.
rg -n '"(preinstall|install|postinstall|prepare)"[[:space:]]*:' \
  -g 'package.json' \
  -g '!**/node_modules/**' \
  "$WORKSPACE_ROOT" || true
```

```bash

  -g 'requirements*.txt' \
```

```bash
# Surface registry and release configuration files without printing token values.

  -not -path '*/node_modules/*' \
```

## Copy/Paste Remediation

```bash
# Node incident triage path when install-time compromise is suspected.
npm ci --ignore-scripts
npm audit --audit-level=high
```

```bash
# Python incident triage path when package compromise may affect your dependency set.
python -m pip check
python -m pip list --outdated
pip-audit || true
```

```bash
# Release-pipeline hardening checklist.
# - Prefer npm or PyPI trusted publishing over long-lived publish tokens when supported.
# - Isolate publishing into a dedicated workflow and protected environment.
# - Grant id-token: write only to the job that must mint an OIDC token.
# - Scope OIDC trust by repository, workflow file, ref, environment, audience, and subject claims.
# - Pin third-party GitHub Actions by full commit SHA.
# - Keep issue text, PR text, comments, branch names, tool output, and model output out of direct shell execution.
# - Require review before enabling self-hosted, privileged, or network-adjacent runners.
true
```

```bash
# Package install hardening checklist.
# - Use lockfiles with hashes where available.
# - Prefer exact versions for high-trust packages and enforce lockfile use in CI.
# - Add a package-age cooldown policy for routine non-security updates.
# - Bypass cooldowns deliberately only for verified security updates.
# - Compare critical registry artifacts against source tags, attestations, and expected publish workflows.
# - If compromise is plausible, rotate affected GitHub, registry, cloud, webhook, SSH, signing, database, and AI-provider credentials through approved account UIs.
true
```

```bash
# Agent, MCP, editor, and extension hardening checklist.
# - Open unfamiliar repositories in restricted or untrusted mode first.
# - Treat MCP manifests, tool descriptions, extension recommendations, workspace settings, tasks, and devcontainers as code.
# - Review new local agents, MCP servers, extension publishers, and tool permissions before enabling them.
# - Require explicit human approval for tools that can mutate files, publish packages, call cloud APIs, or trigger CI/CD.
# - Keep agent-accessible credentials out of workspaces, dependency folders, issue text, prompts, and CI logs.
# - Use AI review as one triage signal, then confirm with deterministic scanning, provenance checks, sandboxing, and human review.
true
```
