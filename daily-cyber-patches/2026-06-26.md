Mode: Public defensive guidance. No private environment data included.

## Executive Summary

- Fresh public reporting continues to cluster around developer infrastructure: compromised npm packages, mutable GitHub Action tag hijacks, OIDC publishing trust, runner credential exposure, and AI/editor configuration abuse.
- The live CISA KEV catalog is version 2026.06.25, released 2026-06-25T19:03:21.8037Z. New June 25 entries for PTC Windchill/FlexPLM and Cisco Unified CM are due by 2026-06-28; several June 23 Ubiquiti and Lantronix entries are due today, 2026-06-26.
- Treat package installs, package imports, GitHub Actions, OIDC publishing, MCP tools, agent rules, workspace tasks, and editor extensions as privileged code paths. Review origin, permissions, runtime behavior, and rollback plans before enabling or updating them.

## Copy/Paste Remediation

```bash
# Node incident triage path when install-time compromise is suspected.
npm ci --ignore-scripts
npm audit --audit-level=high
```

```bash
# Python incident triage path when package compromise may affect your dependency set.
python -m pip check
python -m pip list --outdated
pip-audit || true
```

```bash
# GitHub Actions hardening checklist.
# - Replace reported compromised actions before re-running affected workflows.
# - Pin third-party actions to reviewed full commit SHAs or immutable releases.
# - Restrict GITHUB_TOKEN with job-level permissions.
# - Grant id-token: write only to the publish/deploy job that must mint OIDC tokens.
# - Put publishing in a dedicated workflow and protected environment.
# - Bind OIDC trust to exact repository, workflow file, ref, environment, audience, and subject claims.
# - Treat issue text, pull request text, comments, branch names, tool output, and model output as untrusted input.
# - Require review before enabling self-hosted, privileged, or network-adjacent runners.
true
```

```bash
# Package install hardening checklist.
# - Rebuild affected runners and developer environments from clean images before trusting results.
# - Rotate affected GitHub, registry, cloud, webhook, SSH, signing, database, and AI-provider credentials through approved account UIs if exposure is plausible.
# - Use lockfiles with hashes where available and enforce lockfile use in CI.
# - Add package-age cooldowns for routine non-security dependency updates.
# - Bypass cooldowns deliberately only for verified security fixes.
# - Compare critical registry artifacts against source tags, attestations, expected publishers, and expected workflow identities.
# - Remove stale maintainer and automation accounts from package registries and review registered trusted publishers during offboarding.
true
```

```bash
# Agent, MCP, editor, and extension hardening checklist.
# - Open unfamiliar repositories in restricted or untrusted mode first.
# - Treat MCP manifests, tool descriptions, extension recommendations, workspace settings, tasks, devcontainers, and agent skills as code.
# - Review local agents, MCP servers, extension publishers, tool schemas, and tool permissions before enabling them.
# - Require explicit human approval for tools that can mutate files, publish packages, call cloud APIs, or trigger CI/CD.
# - Keep agent-accessible credentials out of workspaces, dependency folders, issue text, prompts, and CI logs.
# - Use AI review as one triage signal, then confirm with deterministic scanners, provenance checks, sandboxing, and human review.
true
```
