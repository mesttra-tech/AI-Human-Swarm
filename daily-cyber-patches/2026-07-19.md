# Daily Cyber Patch - 2026-07-19

Mode: Public defensive guidance. No private environment data included.

## Executive Summary

- Today is the CISA Known Exploited Vulnerabilities remediation deadline for FortiSandbox CVE-2026-39808 and CVE-2026-25089 and on-premises SharePoint Server CVE-2026-58644. Patch or isolate applicable systems and investigate for prior exploitation; a version change alone does not clear historical compromise.
- GitHub's public advisory feed published 12 npm malware records after the previous completed patch cutoff. Search manifests and lockfiles without installing or importing the packages, and treat plausible SDK, UI-kit, telemetry, and vendor-like names as untrusted until independently approved.
- Prepare for two July 20 GitHub Actions changes: unsupported self-hosted runners in Enterprise Cloud with Data Residency enter a configuration-and-runtime brownout, and safer `pull_request_target` behavior is scheduled to reach supported `actions/checkout` versions. Review pinned checkout SHAs and privileged workflow patterns rather than assuming a backport will reach every workflow automatically.
- Package-manager configuration can leak credentials before lifecycle scripts run. Update affected pnpm branches, scope registry credentials to their intended host, and treat repository-controlled `.npmrc` and workspace configuration as executable trust-boundary input.

## Copy/Paste Assessment

Run only checks that match systems you own or administer. These commands enumerate names and configuration locations; they do not print credential values.

```bash
# Set this placeholder to the workspace you are authorized to assess.
export WORKSPACE_ROOT="<WORKSPACE_ROOT>"
cd "$WORKSPACE_ROOT"
```

```bash
# Locate dependency manifests and lockfiles without traversing installed dependencies.
find "$WORKSPACE_ROOT" -type f \( \
  -name package.json -o \
  -name package-lock.json -o \
  -name pnpm-lock.yaml -o \
  -name pnpm-workspace.yaml -o \
  -name yarn.lock -o \
  -name requirements.txt -o \
  -name pyproject.toml -o \
  -name uv.lock -o \
  -name poetry.lock \
\) -not -path '*/node_modules/*' -not -path '*/.venv/*' -print
```

```bash
# Review manifests and lockfiles for names in the 12 npm malware records published
# after the previous completed cutoff. A hit is an assessment trigger; do not run it.
rg -n '@edgecommons/edgecommons|@edgecommons/streamlog-node|@injectivelabs/sdk-ts|axios-native|easyway2|govpkg|syft-acp-atoms|syft-acp-core|syft-acp-uikit|telemetry-axios|trongridev|trongridme' \
  -g 'package.json' -g 'package-lock.json' -g 'pnpm-lock.yaml' -g 'yarn.lock' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Review install-time scripts. Their absence does not prove runtime safety.
rg -n '"(preinstall|install|postinstall|prepare)"[[:space:]]*:' \
  -g 'package.json' -g '!**/node_modules/**' \
  "$WORKSPACE_ROOT" || true

# Identify registry-auth files and report only files containing auth markers.
find "$WORKSPACE_ROOT" \( -name .npmrc -o -name auth.ini \) -type f \
  -not -path '*/node_modules/*' -not -path '*/.git/*' -print
rg --files-with-matches --hidden -i '(_authToken|_password|tokenHelper|NPM_TOKEN|npm_[A-Za-z0-9]{20,})' \
  -g '.npmrc' -g 'auth.ini' -g '!**/.git/**' -g '!**/node_modules/**' \
  "$WORKSPACE_ROOT" || true

# Report the package-manager version without printing configuration or credentials.
pnpm --version
```

```bash
# Review workflow triggers, privileges, release paths, runner type, and action references.
if [ -d "$WORKSPACE_ROOT/.github/workflows" ]; then
  rg -n 'pull_request_target|workflow_run|id-token:[[:space:]]*write|contents:[[:space:]]*write|packages:[[:space:]]*write|npm publish|permissions:|runs-on:[[:space:]]*self-hosted|actions/checkout@|uses:' \
    "$WORKSPACE_ROOT/.github/workflows" || true
fi
```

```bash
# Inventory repository-scoped agent, MCP, editor, and startup configuration by filename.
find "$WORKSPACE_ROOT" -type f \( \
  -name 'mcp.json' -o \
  -name '.mcp.json' -o \
  -name 'settings.json' -o \
  -name 'extensions.json' -o \
  -name 'tasks.json' -o \
  -name 'AGENTS.md' \
\) -not -path '*/node_modules/*' -not -path '*/.git/*' -print

# Review tool endpoints, automatic approval, allowed tools, and extension recommendations.
rg -n 'mcpServers|streamableHttp|serverUrl|autoApprove|allowedTools|recommendations' \
  -g '*.json' -g '*.jsonc' -g '*.toml' -g '*.yaml' -g '*.yml' \
  -g '!**/node_modules/**' -g '!**/.git/**' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Search owned inventories and documentation for today's KEV deadline products.
rg -n -i 'FortiSandbox|SharePoint Server' \
  -g '*sbom*' -g '*.cdx.json' -g '*.spdx.json' -g '*.md' -g '*.yaml' -g '*.yml' \
  "$WORKSPACE_ROOT" || true
```

Assessment notes:

- A manifest or lockfile hit establishes possible exposure, not execution. Correlate it with install, import, build, test, editor, endpoint, and CI history.
- No lockfile hit does not clear globally installed, dynamically fetched, cached, vendored, previously removed, or editor-managed packages.
- Do not investigate suspected malware by importing, installing, or executing it on a normal workstation. Use the organization's isolated analysis and incident-response process.
- A lifecycle-script block does not stop package-manager configuration processing, package imports, CLIs, tests, build plugins, editor activation, or later execution.
- Verify security appliances and SharePoint versions through vendor-supported inventory. Do not probe systems you do not own or administer.

## Copy/Paste Remediation

For a Node project with a reviewed lockfile and no evidence of compromise:

```bash
# Rebuild from the reviewed lockfile while suppressing lifecycle scripts during initial inspection.
npm ci --ignore-scripts
npm audit --audit-level=high
npm test
```

For pnpm:

- Upgrade affected pnpm 10 deployments to 10.34.2 or later and affected pnpm 11 deployments to 11.5.3 or later; prefer the current supported release after reviewing its changelog.
- Bind each registry credential to its exact intended host. Remove deprecated unscoped authentication settings and do not let repository-controlled configuration select the destination for a credential defined elsewhere.
- Treat a lockfile-integrity mismatch as a security event to investigate. Do not refresh checksums until the new artifact and publisher path have been independently reviewed.

If a malicious package was installed, imported, or executed, or if affected pnpm configuration could reach credentials:

1. Stop using the affected environment for credentialed development, builds, releases, and deployments.
2. Preserve relevant endpoint, process, package-manager, CI, source-control, registry, and identity logs under the incident-response policy.
3. Rebuild the workstation or runner from a known-good image rather than trusting package removal alone.
4. Restore a reviewed lockfile and use a maintainer-confirmed package and release.
5. Rotate credentials reachable from the affected process through the relevant account, cloud, registry, signing, or secret-manager interface. Revoke active sessions and review audit logs.
6. Rebuild and compare artifacts from reviewed source before restoring publication or deployment access.

For GitHub Actions, OIDC, and runners:

```yaml
# Start every workflow with no token permissions; grant only what each job requires.
permissions: {}
```

- Never check out or execute untrusted pull-request code in a privileged `pull_request_target` job.
- Upgrade supported `actions/checkout` versions through a reviewed commit SHA after the July 20 backport; version 1 is excluded, and SHA-, minor-, or patch-pinned workflows do not receive floating-tag updates automatically.
- Protect every branch and tag that can trigger a release. Require reviewed changes and environment approval for publication.
- Pin third-party actions to reviewed commit SHAs and use dependency tooling to keep pins current.
- Separate `id-token: write`, repository writes, and package publication into minimal jobs.
- Use ephemeral isolated runners for untrusted code. Update runner binaries, images, bootstrap automation, and cached templates together.
- Validate immutable OIDC owner and repository IDs, audience, branch, reusable workflow, and environment conditions in non-production.

For MCP, agents, package selection, and editor extensions:

- Deny new packages, servers, tools, extensions, endpoints, and permissions by default; approve the exact publisher, repository, version, endpoint, and capability.
- Treat tool descriptions, package READMEs, retrieved documents, issue text, web pages, and persistent memory as untrusted data, never as authorization.
- Authenticate local control planes, validate origins, bind network services to the narrowest interface, and isolate browsing from privileged tool execution.
- Require human approval for credential use, external writes, publication, deployment, destructive actions, and scope expansion.
- Bind each agent or MCP server to a dedicated least-privilege identity and narrow network destinations.
- Revoke approval when metadata, ownership, binary, endpoint, dependencies, or requested permissions change.
- Disable workspace extension recommendations and automatic task execution for untrusted repositories until reviewed.

For exploited products:

- Follow CISA-required actions and the current vendor advisory. Patch supported systems, isolate unsupported systems, and discontinue products that cannot be mitigated.
- Prioritize FortiSandbox CVE-2026-39808 and CVE-2026-25089 and SharePoint CVE-2026-58644 today.
- Investigate relevant authentication, administrative, application, and network activity. Patching closes the vulnerability but does not erase prior exploitation.

Verify operationally:

- A clean ephemeral CI run succeeds from the reviewed commit using the updated lockfile, pinned actions, and current runner image.
- A staged release requires the intended protected branch, workflow, identity, and approval; an unauthorized non-production source cannot publish.
- Cloud federation succeeds only for the intended immutable GitHub subject and audience; a deliberately unauthorized request is denied.
- Package-registry, GitHub, cloud, identity, and signing logs show no unexplained actions after containment and credential rotation.
- MCP and agent tests demonstrate that untrusted content cannot grant permissions, add tools, change durable memory without review, reach privileged local control planes, or trigger external writes without approval.
- Editor inventory matches the organization allowlist and endpoint tooling reports no blocked or quarantined extension.
- Product owners record the remediated version, deployment date, exposure review, and incident-triage result for every applicable KEV item.

## Not Applicable / Not Tested

- This is passive, public defensive guidance, not a scan of any private repository, workstation, runner, cloud account, appliance, SharePoint farm, package registry, MCP server, agent, editor, or production system.
- No private dependency graph, installed package set, endpoint telemetry, workflow history, cloud trust policy, secret store, registry account, or vulnerability-scanner result was inspected.
- The 12 malware advisories were counted from GitHub's public API after the previous completed patch cutoff; all were npm records in that query. No PyPI malware record matched the same ecosystem and time filter. This does not prove that PyPI or another ecosystem had no new malicious packages.
- Package names establish public advisory records, not exposure in any environment or attribution to one campaign.
- CISA KEV deadlines apply directly to US federal civilian agencies; other organizations should use KEV inclusion as a strong prioritization signal and follow their own obligations.
- Vendor affected-version matrices, exploit details, and product-specific indicators were not reproduced. Consult current vendor advisories for exact applicability.
- Microsoft states the specific AutoJack MCP WebSocket surface was fixed during development and was never present in a PyPI AutoGen Studio release. It is included for its general defensive lesson, not as a claim that current PyPI users are exposed to that chain.
- The July 20 runner brownout applies to GitHub Enterprise Cloud with Data Residency. The `actions/checkout` change has separate version and pinning conditions described in GitHub's changelog.
- AI-assisted intrusion claims rely partly on vendor observations and evolving attribution. The defensive recommendations do not depend on claims of fully autonomous attacks.
