# Daily Cyber Patch - 2026-06-27

Mode: Public defensive guidance. No private environment data included.

## Executive Summary

- The live CISA Known Exploited Vulnerabilities (KEV) feed remains at catalog version 2026.06.25. Cisco Unified Communications Manager CVE-2026-20230 and PTC Windchill/FlexPLM CVE-2026-12569 are due 2026-06-28; four Ubiquiti and Lantronix items passed their KEV due date on 2026-06-26.
- Recent npm and PyPI reporting continues to show that package installation, Python interpreter startup, native-build metadata, CI runners, OIDC publishing, and editor/agent configuration are one connected credential boundary. A clean registry `latest` tag or valid provenance record is not enough when a lockfile, runner, or publishing workflow was compromised.
- Treat GitHub Actions, MCP servers, agent tools, editor extensions, workspace settings, package manifests, lockfiles, `.pth` startup hooks, and `binding.gyp` files as privileged code. Isolate suspected systems before rotating credentials, rebuild affected runners, and verify publishing identities and workflow history.

## Copy/Paste Assessment

Run only the checks that match your environment. These commands should not print secret values.

```bash
# Set this to your local workspace before running checks.
export WORKSPACE_ROOT="<WORKSPACE_ROOT>"
cd "$WORKSPACE_ROOT"
```

```bash
# Pull current CISA KEV data for patch prioritization.
curl -fsSL https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json -o kev.json
jq -r '.catalogVersion, .dateReleased, (.vulnerabilities | sort_by(.dateAdded) | reverse | .[] | select(.dateAdded >= "2026-06-01") | [.dateAdded,.dueDate,.cveID,.vendorProject,.product,.knownRansomwareCampaignUse] | @tsv)' kev.json
```

```bash
# Find package manifests, lockfiles, registry configs, native-build metadata, and Python startup hooks.
find "$WORKSPACE_ROOT" -type f \( \
  -name package.json -o \
  -name package-lock.json -o \
  -name npm-shrinkwrap.json -o \
  -name pnpm-lock.yaml -o \
  -name yarn.lock -o \
  -name requirements.txt -o \
  -name pyproject.toml -o \
  -name pylock.toml -o \
  -name uv.lock -o \
  -name binding.gyp -o \
  -name '*.pth' -o \
  -name .npmrc -o \
  -name .pypirc \
\) -not -path '*/node_modules/*' -not -path '*/.venv/*' -print
```

```bash
# Review Node package lifecycle scripts without executing them.
rg -n '"(preinstall|install|postinstall|prepare)"[[:space:]]*:' \
  -g 'package.json' \
  -g '!**/node_modules/**' \
  "$WORKSPACE_ROOT" || true
```

```bash

  -g 'package.json' \
  -g 'package-lock.json' \
  -g 'npm-shrinkwrap.json' \
  -g 'pnpm-lock.yaml' \
  -g 'yarn.lock' \
  -g 'requirements*.txt' \
  -g 'pyproject.toml' \
  -g 'uv.lock' \
  -g '!**/node_modules/**' \
  -g '!**/.venv/**' \

```

```bash
# Identify files that appear to contain registry credentials without printing their contents.
rg --files-with-matches --hidden -i '(_authToken|NPM_TOKEN|NODE_AUTH_TOKEN|PYPI_TOKEN|TWINE_PASSWORD|npm_[A-Za-z0-9]{20,}|pypi-[A-Za-z0-9]{20,})' \
  -g '.npmrc' \
  -g '.pypirc' \
  -g 'package.json' \
  -g 'pyproject.toml' \
  -g '.github/workflows/*.yml' \
  -g '.github/workflows/*.yaml' \
  -g '!**/.git/**' \
  -g '!**/node_modules/**' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Review workflows for reported compromised actions, risky triggers, broad permissions, OIDC minting, and untrusted event context.
rg -n '(codfish/semantic-release-action|simonecorsi/mawesome|pull_request_target|workflow_run|issue_comment|repository_dispatch|id-token:[[:space:]]*write|permissions:[[:space:]]*write-all|secrets:[[:space:]]*inherit|github\.event\..*(title|body|head_ref|ref|label|message|name))' \
  -g '.github/workflows/*.yml' \
  -g '.github/workflows/*.yaml' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Find third-party actions that are not pinned to a full 40-character commit SHA.
rg -n 'uses:[[:space:]]*[^[:space:]]+/[^[:space:]@]+@[^#[:space:]]+' \

  -g '.github/workflows/*.yaml' \
  "$WORKSPACE_ROOT" | rg -v '@[0-9a-f]{40}([[:space:]#]|$)' || true
```

```bash
# Node incident-triage mode when install-time compromise is suspected.
npm ci --ignore-scripts

```

```bash
# Python dependency integrity checks. Review findings before changing versions.

pip-audit || true
```

```bash
# CI/CD and publishing hardening checklist.
# - Replace reported compromised actions before re-running affected workflows.
# - Pin third-party actions to reviewed full commit SHAs or immutable releases.
# - Restrict GITHUB_TOKEN with job-level permissions.
# - Grant id-token: write only to the publish/deploy job that must mint OIDC tokens.
# - Bind OIDC trust to the exact repository, workflow file, ref, environment, audience, and subject claims.
# - Put package publishing behind a dedicated workflow and protected environment.
# - Treat issue text, pull request text, comments, branch names, tool output, and model output as untrusted input.
# - Use ephemeral or freshly rebuilt runners for privileged release jobs.
true
```

```bash
# Package and incident-response hardening checklist.
# - Isolate suspected systems before credential rotation or destructive cleanup.
# - Rebuild affected runners and developer environments from clean images.
# - Rotate affected GitHub, registry, cloud, signing, SSH, database, webhook, and AI-provider credentials through approved account UIs if exposure is plausible.
# - Pin to reviewed clean versions and regenerate lockfiles from a trusted system.
# - Compare registry artifacts with source tags, attestations, expected publishers, and expected workflow identities.
# - Review native-build metadata and Python startup hooks, not only package lifecycle scripts.
# - Remove stale maintainer and automation accounts and review trusted-publisher bindings during offboarding.
true
```

```bash
# Agent, MCP, editor, and extension hardening checklist.
# - Open unfamiliar repositories in restricted or untrusted mode first.
# - Treat MCP manifests, tool descriptions, extension recommendations, workspace settings, tasks, devcontainers, and agent rules as code.
# - Require explicit authorization and human approval for tools that mutate files, publish packages, call cloud APIs, or trigger CI/CD.
# - Separate read-only discovery tools from write-capable tools and keep credentials outside agent-visible workspaces.
# - Validate tool output before it becomes another tool's input.
# - Use AI review as one triage signal, then confirm with deterministic scanners, provenance checks, sandboxing, and human review.
true
```
