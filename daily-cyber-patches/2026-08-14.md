# Daily Cyber Patch - 2026-08-14

Mode: Public defensive guidance. No private environment data included.

## Executive Summary

- CISA KEV catalog version `2026.08.11` lists Cisco ASA/FTD CVE-2026-20349 and Metabase CVE-2026-72898 with remediation deadlines today, August 14. Microsoft Windows CVE-2026-68820 is due August 25. Treat KEV inclusion as confirmed exploitation and use vendor-supported inventory and fixes.
- A GitHub Advisory Database snapshot taken August 14 returned 163 malware records published after the prior scheduler cutoff: all 163 were npm records, covering 161 unique package names. This is catalog activity, not a count of campaigns, uploads, installations, executions, or compromises.
- Representative records show distinct install-time, import/runtime, MCP-startup, and background-process activation paths. Blocking lifecycle scripts helps with only one path; exact lockfile matching, clean rebuilds, endpoint review, and credential decisions remain necessary.
- Fresh reviewed npm and PyPI advisories also affect runtime secrets and agent trust boundaries, including `hashi-vault-js`, Pydantic AI, NLTK, Trigger.dev, and MCP-for-Stata. Patch or contain based on exact affected versions and reachable inputs.
- AI-assisted threat research shows attackers applying AI deeper in the intrusion lifecycle. Defenders should use AI to accelerate inventory correlation and review, while preserving human authorization for containment, credential rotation, publication, and destructive actions.

## Copy/Paste Assessment

Run only checks that match your environment. These commands report filenames, package identities, configuration lines, or workflow metadata; they are not intended to print secret values.

```bash
# Set this to the repository or workspace you are authorized to review.
export WORKSPACE_ROOT="<WORKSPACE_ROOT>"
cd "$WORKSPACE_ROOT"
```

```bash
# Find package manifests, lockfiles, and repository-controlled package-manager configuration.
find "$WORKSPACE_ROOT" -type f \( \
  -name package.json -o -name package-lock.json -o \
  -name npm-shrinkwrap.json -o -name pnpm-lock.yaml -o \
  -name pnpm-workspace.yaml -o -name yarn.lock -o \
  -name requirements.txt -o -name pyproject.toml -o \
  -name poetry.lock -o -name uv.lock -o -name .npmrc \
\) -not -path '*/node_modules/*' -not -path '*/.venv/*' -print
```

```bash
# Review lifecycle hooks and non-registry dependency sources without running them.
rg -n '"(preinstall|install|postinstall|prepare)"[[:space:]]*:' \
  -g 'package.json' -g '!**/node_modules/**' "$WORKSPACE_ROOT" || true

rg -n '"[^"]+"[[:space:]]*:[[:space:]]*"(git\\+|github:|gitlab:|https?://|file:)' \
  -g 'package.json' -g '!**/node_modules/**' "$WORKSPACE_ROOT" || true
```

Assessment cautions:

- Do not infer one actor, one campaign, current installation, execution, or equal severity from advisory counts, similar names, or concentrated publication timestamps.
- Advisory publication time is not package upload, installation, execution, or compromise time.
- Do not investigate suspected malware by installing, importing, restoring, invoking, or executing it on a normal workstation.
- Install-script blocking does not stop imports, CLIs, tests, plugins, editor activation, MCP startup, startup-file processing, native modules, hooks, scheduled tasks, or later execution.
- Registry scanning, marketplace badges, provenance, signatures, and OIDC attest selected trust properties; none proves that source, workflows, dependencies, artifacts, or runtime behavior are benign.
- Verify affected product versions through vendor-supported inventory. Do not probe systems you do not own or administer.

## Copy/Paste Remediation

For a Node project with a reviewed lockfile and no evidence of compromise:

```bash
# Rebuild from the reviewed lockfile while suppressing lifecycle scripts during initial inspection.
npm ci --ignore-scripts
npm audit --audit-level=high
npm test
```

For a Python project with a reviewed lockfile and no evidence of compromise:

```bash
# Create a clean environment, then use the project's approved lockfile workflow.
python -m venv .venv-review
. .venv-review/bin/activate
python -m pip install --upgrade pip
python -m pip check
python -m pip list
```

Do not reinstall or import a suspected package merely to inspect it. Use the package index, advisory record, retained artifact, or an isolated malware-analysis process approved by your incident-response team.

Package, runtime, and registry controls:

- Match exact package name, scope, ecosystem, registry, version, resolved artifact, and integrity data against the live advisory feed. Do not rely on visual similarity alone.
- Use a release cooldown so brand-new versions do not enter production immediately. Keep urgent security updates on a separately reviewed path.
- Prefer default-deny installation behavior for dependency scripts, native builds, Git dependencies, and remote dependencies. Approve only exact required packages and sources.
- Pin dependencies with reviewed lockfiles and hashes where supported. Re-review publisher, ownership, registry host, resolved files, permissions, dependencies, lifecycle hooks, native modules, and runtime behavior.
- Prevent secret-bearing objects from entering exceptions or logs. Patch `hashi-vault-js` when a maintained fix is available; until then, avoid affected versions or place a reviewed redaction boundary around errors and rotate any value already recorded.
- Upgrade Pydantic AI to `1.106.0` or later, or `2.0.0b6` or later on the beta line. Validate client-supplied file references against the authenticated caller and an explicit allowlist.
- Upgrade MCP-for-Stata to `1.19.0` or later and validate tool arguments as data. Do not pass untrusted values into interpreters, shells, package installers, or command construction.
- Upgrade NLTK, Trigger.dev, and other affected runtime packages outside the listed ranges. Apply request limits, input normalization, tenant isolation, and regression tests appropriate to the advisory.
- Prefer short-lived trusted publishing over long-lived registry tokens. Protect the workflow, environment, branch, repository identity, and human approval that can publish.

If a malicious package, extension, MCP server, or agent tool was installed, imported, restored, invoked, or executed:

1. Stop using the affected environment for credentialed development, builds, releases, and deployments.
2. Isolate it and preserve relevant endpoint, process, editor, package-manager, CI, source-control, registry, identity, agent, and signing logs under the incident-response policy.
3. Rebuild the workstation or runner from a known-good image rather than trusting component removal alone.
4. Restore reviewed lockfiles, environments, extensions, MCP servers, tools, workflows, caches, artifacts, startup files, scheduled tasks, and hooks from known-good sources.
5. Rotate credentials reachable from the affected process through the relevant account, cloud, registry, signing, or secret-manager interface. Revoke active sessions and review audit logs.
6. Rebuild and compare release artifacts from reviewed source before restoring publication or deployment access.

For GitHub Actions, OIDC, caches, and runners:

```yaml
# Start every workflow with no token permissions; grant only what each job requires.
permissions: {}
```

- Treat a held run as a security review queue, not a routine confirmation prompt.
- Never execute untrusted pull-request code in a privileged `pull_request_target`, `workflow_run`, comment-triggered, release, or publication job.
- Separate repository writes, `id-token: write`, cache writes, artifact promotion, signing, and publication into minimal reviewed jobs.
- Pin third-party actions to reviewed full commit SHAs and keep pins current.
- Protect every branch, tag, environment, and reusable workflow that can publish or deploy. Require review for production environments.
- Validate immutable owner and repository IDs, issuer, audience, branch, environment, and reusable-workflow conditions in cloud trust policies.
- Use ephemeral isolated runners for untrusted code. Update runner binaries, base images, bootstrap automation, and cached templates together.
- Treat caches and artifacts crossing trust levels as untrusted inputs. Verify origin and content before privileged consumption.
- Enable secret scanning and push protection where available. Detection requires provider-side revocation or rotation and activity review; deleting the latest copy is not sufficient.

For MCP, agents, and editor extensions:

- Deny new packages, servers, tools, extensions, endpoints, and permissions by default. Approve exact publisher, repository, version, endpoint, metadata, and capability.
- Treat tool descriptions, schemas, returned content, package documentation, retrieved files, issue text, web pages, code comments, workspace rules, and durable memory as untrusted data, never authorization.
- Review the complete local MCP startup command before execution. Sandbox the server, restrict filesystem and network access, and do not expose unauthenticated local services to browser-reachable origins.
- Require HTTPS for production authorization endpoints, exact redirect-URI matching, per-client consent, short-lived state, token audience validation, and protected-resource binding. Do not pass upstream tokens through to downstream services.
- Restrict OAuth metadata discovery and redirect destinations with validated egress policy so they cannot reach private, loopback, link-local, or cloud-metadata addresses unless explicitly required and isolated.
- Open unfamiliar workspaces in Restricted Mode. Enable agent and local-MCP sandboxing where supported; restrict file and network access.
- Keep auto-approval scoped to the session. Require manual approval for terminal execution, network fetches, credential use, external writes, publication, deployment, destructive actions, and scope expansion.
- Re-review tool descriptions and schemas when a server reports changes. Display the exact changed capabilities before granting trust again.
- Inventory editor extensions centrally where possible. Allowlist publisher and extension identities, review dependency and permission changes, and remove abandoned or unexpected extensions.

For the three current KEV items:

- Cisco ASA/FTD CVE-2026-20349: identify affected remote-access VPN appliances, follow Cisco’s fixed-software guidance, preserve required forensic data, and validate service health after upgrade.
- Metabase CVE-2026-72898: identify self-hosted instances, restrict exposure until upgraded, use the current Metabase security update for supported fixed releases, and review authentication, query, application, and database-access logs under the incident-response policy.
- Windows CVE-2026-68820: deploy the current Microsoft security update through the normal endpoint-management process and verify build/update compliance before the August 25 deadline.

Defensive AI use:

- Use AI to correlate advisory identities with approved SBOMs, lockfiles, images, extension inventories, MCP manifests, workflows, and endpoint telemetry.
- Require the model to cite the exact record and affected range for every match. Human reviewers must confirm package identity, source, version semantics, reachability, and remediation.
- Do not give a triage agent unrestricted access to secrets, production mutation, publication, or destructive tools. Keep evidence retrieval separate from action authorization.
- Test detections with known-safe fixtures and synthetic metadata. Do not execute live malicious packages or copy public proof-of-concept payloads into normal environments.

Verification evidence should include:

- Exact affected and remediated package, product, extension, MCP server, action, runner, or editor version.
- Lockfile or artifact diff, clean rebuild source, test results, scanner results, and unresolved exceptions.
- For KEV items, vendor-supported fixed release, deployment time, exposure decision, health checks, and vendor-directed forensic outcome.
- For suspected code execution, containment time, known-good rebuild, credential categories rotated, sessions revoked, audit review, and artifact provenance comparison.
- For GitHub Actions and OIDC, effective permissions, trigger policy, action pins, environment protections, trust-policy issuer/audience/subject conditions, runner image/version, and cache/artifact boundaries.
- For MCP, agents, and editors, approved publisher, exact version, startup command, tool/schema hash or diff, filesystem/network scope, OAuth audience, sandbox policy, auto-approval policy, and trust reauthorization result.

Success means the risky identity or version is absent or formally accepted, relevant credentials and sessions were handled, clean artifacts were rebuilt, runtime and delayed-activation paths were reviewed, and verification evidence was retained. Deleting a package or suppressing install scripts alone is not proof of recovery.
