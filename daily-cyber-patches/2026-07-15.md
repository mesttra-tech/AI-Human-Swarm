# Daily Cyber Patch - 2026-07-15

Mode: Public defensive guidance. No private environment data included.

## Executive Summary

- Treat any installation or execution of affected Jscrambler npm releases as a potential developer-workstation or CI compromise. The malicious delivery moved from install-time hooks to package import and CLI execution, so disabling lifecycle scripts alone is not a complete control.
- CISA added four vulnerabilities to the Known Exploited Vulnerabilities catalog on July 14: two SonicWall SMA1000 flaws, one Microsoft SharePoint Server flaw, and one Microsoft AD FS flaw. Inventory affected products now; the first three have a July 17 remediation deadline.
- GitHub's immutable Actions OIDC subject format takes effect today for new repositories and for repositories renamed or transferred after today. Cloud trust policies that assume the older name-only subject format need coordinated review.
- GitHub Enterprise Cloud with Data Residency is also running a self-hosted-runner registration and runtime brownout today. Update runner images and verify that jobs are not stranded on stale runners.
- Keep AI agents, MCP servers, and editor extensions behind explicit allowlists, least-privilege identities, immutable configuration review, and human approval for consequential actions. Recent research continues to show that AI can accelerate established attack techniques while poisoned tool metadata, retrieved content, or memory can redirect legitimate agents.

## Copy/Paste Assessment

Run only checks that match your environment. These commands enumerate names and configuration locations; they do not print credential values.

```bash
# Set this placeholder to the workspace you are authorized to assess.
export WORKSPACE_ROOT="<WORKSPACE_ROOT>"
cd "$WORKSPACE_ROOT"
```

```bash
# Locate package manifests and lockfiles without traversing dependency directories.
find "$WORKSPACE_ROOT" -type f \( \
  -name package.json -o \
  -name package-lock.json -o \
  -name pnpm-lock.yaml -o \
  -name yarn.lock -o \
  -name requirements.txt -o \
  -name pyproject.toml -o \
  -name uv.lock -o \
  -name poetry.lock \
\) -not -path '*/node_modules/*' -not -path '*/.venv/*' -print
```

```bash
# Check resolved Node dependency trees for the Jscrambler packages named in current advisories.
npm ls jscrambler gulp-jscrambler jscrambler-metro-plugin --all || true

# Review lockfiles for affected Jscrambler releases and related package names.
rg -n 'jscrambler|gulp-jscrambler|jscrambler-metro-plugin|8\.14\.0|8\.16\.0|8\.17\.0|8\.18\.0|8\.20\.0' \
  -g 'package-lock.json' -g 'pnpm-lock.yaml' -g 'yarn.lock' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Review install-time scripts. Absence of a lifecycle script does not prove a package is safe.
rg -n '"(preinstall|install|postinstall|prepare)"[[:space:]]*:' \
  -g 'package.json' -g '!**/node_modules/**' \
  "$WORKSPACE_ROOT" || true

# Look for package files associated with the documented Jscrambler delivery paths.
find "$WORKSPACE_ROOT" -type f \( \
  -path '*/node_modules/jscrambler/dist/setup.js' -o \
  -path '*/node_modules/jscrambler/dist/intro.js' -o \
  -path '*/node_modules/jscrambler/dist/bin/jscrambler.js' \
\) -print
```

```bash
# Identify registry-auth files by filename, and only report files containing auth markers.
find "$WORKSPACE_ROOT" -name .npmrc -type f -not -path '*/node_modules/*' -print
rg --files-with-matches --hidden -i '(_authToken|NPM_TOKEN|npm_[A-Za-z0-9]{20,})' \
  -g '.npmrc' -g '!**/.git/**' -g '!**/node_modules/**' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Review workflows for high-risk triggers, federated identity, self-hosted execution, permissions, and mutable action references.
if [ -d "$WORKSPACE_ROOT/.github/workflows" ]; then
  rg -n 'pull_request_target|workflow_run|id-token:[[:space:]]*write|permissions:|runs-on:[[:space:]]*self-hosted|uses:' \
    "$WORKSPACE_ROOT/.github/workflows" || true
fi
```

```bash
# Inventory repository-scoped agent, MCP, editor, and startup configuration by filename.
find "$WORKSPACE_ROOT" -type f \( \
  -name 'mcp.json' -o \
  -name '.mcp.json' -o \
  -name 'settings.json' -o \
  -name 'extensions.json' -o \
  -name 'tasks.json' -o \
  -name 'AGENTS.md' \
\) -not -path '*/node_modules/*' -not -path '*/.git/*' -print

# Review tool definitions, remote MCP endpoints, auto-approval, and recommended extensions.
rg -n 'mcpServers|streamableHttp|serverUrl|autoApprove|allowedTools|recommendations' \
  -g '*.json' -g '*.jsonc' -g '*.toml' -g '*.yaml' -g '*.yml' \
  -g '!**/node_modules/**' -g '!**/.git/**' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Search inventories and documentation for products in the newest CISA KEV additions.
rg -n -i 'SMA1000|SharePoint Server|Active Directory Federation Services|AD FS|Cisco IOS' \
  -g '*sbom*' -g '*.cdx.json' -g '*.spdx.json' -g '*.md' -g '*.yaml' -g '*.yml' \
  "$WORKSPACE_ROOT" || true
```

Assessment notes:

- A lockfile hit establishes possible exposure, not execution. Correlate it with package-install, build, endpoint, and CI job history.
- No lockfile hit does not clear a system if packages were installed globally, fetched dynamically, cached outside the workspace, or later removed.
- `npm audit` primarily identifies known vulnerabilities; compare package names and versions with malware advisories as a separate control.
- For exposed network, identity, or collaboration products, verify the actual appliance/server version through the vendor-supported inventory path. Do not probe systems you do not own or administer.

## Copy/Paste Remediation

For a Node project with a lockfile and no evidence of compromise:

```bash
# Rebuild from the lockfile while suppressing lifecycle scripts during initial inspection.
npm ci --ignore-scripts
npm audit --audit-level=high
npm test
```

If the project directly uses Jscrambler, follow the maintainer advisory and move to a verified clean release. At publication time, the maintainer and Socket identify `8.22.0` as clean; confirm that status again before changing production dependencies.

```bash
# Direct dependencies only: pin the maintainer-verified clean release, review the diff, then test.
npm install --save-exact jscrambler@8.22.0 --ignore-scripts
git diff -- package.json package-lock.json
npm test
npm ls jscrambler --all
```

If an affected package executed, treat the host or runner as potentially compromised:

1. Isolate the system from sensitive workflows and stop using it to build or publish artifacts.
2. Preserve relevant endpoint, package-manager, CI, and identity-provider logs according to the incident-response policy.
3. Rebuild the developer environment or ephemeral runner from a known-good image rather than trusting package removal alone.
4. Rotate credentials that were accessible to the affected process through the relevant account, cloud, registry, signing, or secret-manager interface. Do not paste credential values into terminals, tickets, pull requests, or chat.
5. Revoke active sessions and review package publication, repository, cloud, and signing activity for unauthorized use.

For GitHub Actions and OIDC:

```yaml
# Start every workflow with no token permissions; add only the permissions each job needs.
permissions: {}
```

- Pin third-party actions to reviewed commit SHAs and use dependency tooling to keep pins current.
- Do not execute untrusted pull-request code in a privileged `pull_request_target` job.
- Keep `id-token: write` on the smallest deployment job, protected by environment approval and cloud-side audience, subject, repository, branch, and environment conditions.
- Preview GitHub's immutable subject before enabling it for an existing repository. Update the cloud trust policy first, test in non-production, then opt in.
- Replace persistent self-hosted runners used for untrusted code with ephemeral isolated runners where feasible. Update runner binaries, images, bootstrap automation, and cached templates together.

For MCP, agents, and editor extensions:

- Deny new servers, tools, extensions, and permissions by default; approve exact publisher, package, version, endpoint, and capability.
- Treat tool descriptions, retrieved documents, issue text, web pages, and persistent memory as untrusted data, never as authorization.
- Require human approval for credential use, external writes, package publication, deployment, destructive actions, and scope expansion.
- Bind each agent or MCP server to a dedicated least-privilege identity and narrow network destinations. Do not share a developer's broad session by default.
- Record and review tool-definition, server-endpoint, extension-binary, and permission changes. Revoke approval when metadata or publisher ownership changes.
- Disable workspace extension recommendations and automatic task execution for untrusted repositories until reviewed.

For exploited products:

- Follow CISA-required actions and the applicable vendor advisory. Patch supported systems, isolate unsupported systems, and remove products that cannot be remediated.
- Prioritize internet-facing SonicWall SMA1000 and SharePoint Server systems before the July 17 deadline, then AD FS before July 28.
- Investigate identity and administrative activity around affected products; patching closes the vulnerability but does not erase prior exploitation.


Verify operationally:

- A clean ephemeral CI run succeeds using the updated lockfile, pinned actions, and current runner image.
- Cloud federation succeeds only for the intended immutable GitHub subject, audience, branch, and protected environment; a deliberately unauthorized non-production request is denied.
- Package-registry, GitHub, cloud, and signing audit logs show no unexplained actions after credential rotation.
- MCP and agent tests demonstrate that untrusted content cannot grant permissions, add tools, change memory without review, or trigger external writes without approval.
- Editor inventory matches the organization allowlist and endpoint tooling reports no blocked or quarantined extension.
- Product owners record the remediated version and evidence for each applicable KEV item.
