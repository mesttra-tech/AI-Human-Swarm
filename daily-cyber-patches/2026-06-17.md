# Daily Cyber Patch - 2026-06-17

Mode: Public defensive guidance. No private environment data included.

## Executive Summary

- As of June 17, 2026, the fastest patch lane is still the live CISA KEV feed: the June 16 addition for Widget Factory Joomla Content Editor joins the June 15 Cisco Catalyst SD-WAN Manager and LiteSpeed cPanel Plugin items, while the June 11-12 Ivanti Sentry and Oracle PeopleSoft Enterprise PeopleTools entries are already overdue if still exposed.
- Current supply-chain risk is still dominated by trusted release-path abuse instead of obviously malicious installers: compromised maintainer or GitHub access, minimal workflow changes, OIDC-backed publishing, and package releases that look legitimate unless workflow trust and credential scoping are reviewed together.
- AI-assisted review is now part of the attack surface. Current public research and reporting continue to show prompt injection in GitHub Actions, MCP tool poisoning, and AI-scanner derailment, so humans need explicit approval boundaries, pinned tooling, and strict separation between untrusted text and execution.

## Copy/Paste Assessment

Run only the checks that match your environment. These commands should not print secret values.

```bash
# Set this to your local workspace before running checks.
export WORKSPACE_ROOT="<WORKSPACE_ROOT>"
cd "$WORKSPACE_ROOT"
```

```bash
# Find common Node and Python manifests and lockfiles.
find "$WORKSPACE_ROOT" -type f \( \
  -name package.json -o \
  -name package-lock.json -o \
  -name pnpm-lock.yaml -o \
  -name yarn.lock -o \
  -name requirements.txt -o \
  -name pyproject.toml -o \
  -name pylock.toml -o \
  -name uv.lock \
\) -not -path '*/node_modules/*' -not -path '*/.venv/*' -print
```

```bash
# Review install-time package scripts without executing them.
rg -n '"(preinstall|install|postinstall|prepare)"[[:space:]]*:' \
  -g 'package.json' \
  -g '!**/node_modules/**' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Surface registry and release configuration without printing token values.
find "$WORKSPACE_ROOT" -type f \( -name .npmrc -o -name .pypirc -o -name pyproject.toml \) \
  -not -path '*/node_modules/*' -not -path '*/.venv/*' -print
rg -n '(trusted|publishConfig|provenance|NPM_TOKEN|PYPI_TOKEN|TWINE_PASSWORD|NODE_AUTH_TOKEN)' \
  -g 'package.json' \
  -g '.npmrc' \
  -g '.pypirc' \
  -g 'pyproject.toml' \
  -g '!**/.git/**' \
  -g '!**/node_modules/**' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Review workflows for risky triggers, OIDC minting, unpinned actions, and untrusted interpolation.
rg -n '(pull_request_target|workflow_run|issue_comment|repository_dispatch|id-token:[[:space:]]*write|uses:[[:space:]]*[^@[:space:]]+@[^0-9a-f]|github\\.event\\..*(title|body|head_ref|ref|label|message|name))' \
  -g '.github/workflows/*.yml' \
  -g '.github/workflows/*.yaml' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Surface MCP, editor, and container configuration that deserves manual review in unfamiliar repos.
find "$WORKSPACE_ROOT" -type f \( \
  -path '*/.vscode/extensions.json' -o \
  -path '*/.vscode/settings.json' -o \
  -name 'mcp.json' -o \
  -name 'mcp.yaml' -o \
  -name 'devcontainer.json' -o \
  -path '*/.devcontainer/devcontainer.json' \
\) -print
```

```bash
# Pull current KEV additions for patch prioritization.
curl -fsSL https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json \
  | jq -r '.vulnerabilities | sort_by(.dateAdded) | reverse | .[] | select(.dateAdded >= "2026-06-12") | [.dateAdded,.dueDate,.cveID,.vendorProject,.product] | @tsv'
```

```bash
# Hunt for long-running interpreters after suspicious installs, extension activation, or agent-tool changes.
ps -axo pid,ppid,etime,command | rg '(node|bun|python|ruby|sh)' || true
```

## Copy/Paste Remediation

```bash
# Node triage path when install-time compromise is suspected.
npm ci --ignore-scripts
npm audit --audit-level=high
```

```bash
# Python triage path when package compromise may affect your dependency set.
python -m pip check
python -m pip list --outdated
pip-audit || true
```

```bash
# Release-pipeline hardening checklist.
# - Pin third-party GitHub Actions by full commit SHA.
# - Keep workflow and job permissions minimal, including id-token.
# - Scope OIDC trust by repository, workflow file, ref, and environment or subject claims.
# - Use read-only install tokens where package installation still needs auth.
# - Prefer trusted publishing over long-lived npm or PyPI publish tokens.
# - Keep issue text, PR text, comments, branch names, tool output, and model output out of direct shell execution.
# - Require review before enabling self-hosted or privileged release runners.
true
```

```bash
# Agent and editor hardening checklist.
# - Open unfamiliar repos in restricted or untrusted mode first.
# - Treat MCP manifests, tool descriptions, extension recommendations, and devcontainer files like code.
# - Require review before enabling new local agents, tasks, terminals, or extension publishers.
# - Quarantine suspicious files that appear to carry control text meant for agents or automated reviewers.
# - Rotate affected GitHub, registry, cloud, SSH, webhook, and signing credentials through approved UIs if compromise is suspected.
true
```
