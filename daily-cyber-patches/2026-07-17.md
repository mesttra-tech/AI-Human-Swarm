# Daily Cyber Patch - 2026-07-17

Mode: Public defensive guidance. No private environment data included.

## Executive Summary

- CISA added two FortiSandbox command-injection vulnerabilities, CVE-2026-39808 and CVE-2026-25089, plus SharePoint deserialization vulnerability CVE-2026-58644 to the Known Exploited Vulnerabilities catalog on July 16. All three have a July 19 remediation deadline. The previously listed SonicWall SMA1000 and SharePoint CVEs are due today, and Oracle E-Business Suite CVE-2026-46817 is due July 18.
- GitHub's public advisory feed published 13 npm malware records after the previous patch cutoff. Several use AI-, SDK-, scanner-, or terminal-themed names. Treat names, README claims, provenance badges, and registry popularity as discovery signals rather than authorization to install or run a package.
- Today is a GitHub Enterprise Cloud with Data Residency brownout for unsupported self-hosted runner registration. Immutable Actions OIDC subjects are now active for new, renamed, and transferred repositories; validate cloud trust against repository IDs and keep deployment credentials out of untrusted jobs.
- Runtime and dormant-malware review must go beyond install hooks. Packages, editor extensions, MCP servers, build plugins, tests, CLIs, and agent startup can activate code later, so removal alone does not clear previously reachable credentials or persistent runner state.

## Copy/Paste Assessment

Run only checks that match systems you own or administer. These commands enumerate names and configuration locations; they do not print credential values.

```bash
# Set this placeholder to the workspace you are authorized to assess.
export WORKSPACE_ROOT="<WORKSPACE_ROOT>"
cd "$WORKSPACE_ROOT"
```

```bash
# Locate dependency manifests and lockfiles without traversing installed dependencies.
find "$WORKSPACE_ROOT" -type f \( \
  -name package.json -o \
  -name package-lock.json -o \
  -name pnpm-lock.yaml -o \
  -name yarn.lock -o \
  -name requirements.txt -o \
  -name pyproject.toml -o \
  -name uv.lock -o \
  -name poetry.lock \
\) -not -path '*/node_modules/*' -not -path '*/.venv/*' -print
```

```bash
# Review manifests and lockfiles for selected names from today's npm malware records.
# A hit is an assessment trigger; do not install or import a suspected package.
rg -n 'anthropic-claude-latest|scan-only|theta-sdk-js|terminal-mascot|chain-sdk-js|awesome-terminal|ai-pro-sdk|monogrok|my-tailwind-gutenberg-block|chai-as-const|chai-as-thread' \
  -g 'package.json' -g 'package-lock.json' -g 'pnpm-lock.yaml' -g 'yarn.lock' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Review install-time scripts. Their absence does not prove a package is safe at runtime.
rg -n '"(preinstall|install|postinstall|prepare)"[[:space:]]*:' \
  -g 'package.json' -g '!**/node_modules/**' \
  "$WORKSPACE_ROOT" || true

# Identify registry-auth files by filename and report only files containing auth markers.
find "$WORKSPACE_ROOT" -name .npmrc -type f -not -path '*/node_modules/*' -print
rg --files-with-matches --hidden -i '(_authToken|NPM_TOKEN|npm_[A-Za-z0-9]{20,})' \
  -g '.npmrc' -g '!**/.git/**' -g '!**/node_modules/**' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Review workflow triggers, identity permissions, release paths, runner type, and action references.
if [ -d "$WORKSPACE_ROOT/.github/workflows" ]; then
  rg -n 'pull_request_target|workflow_run|id-token:[[:space:]]*write|contents:[[:space:]]*write|packages:[[:space:]]*write|npm publish|permissions:|runs-on:[[:space:]]*self-hosted|uses:' \
    "$WORKSPACE_ROOT/.github/workflows" || true
fi
```

```bash
# Inventory repository-scoped agent, MCP, editor, and startup configuration by filename.
find "$WORKSPACE_ROOT" -type f \( \
  -name 'mcp.json' -o \
  -name '.mcp.json' -o \
  -name 'settings.json' -o \
  -name 'extensions.json' -o \
  -name 'tasks.json' -o \
  -name 'AGENTS.md' \
\) -not -path '*/node_modules/*' -not -path '*/.git/*' -print

# Review tool endpoints, automatic approval, allowed tools, and extension recommendations.
rg -n 'mcpServers|streamableHttp|serverUrl|autoApprove|allowedTools|recommendations' \
  -g '*.json' -g '*.jsonc' -g '*.toml' -g '*.yaml' -g '*.yml' \
  -g '!**/node_modules/**' -g '!**/.git/**' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Search owned inventories and documentation for newly exploited and imminent-deadline products.
rg -n -i 'FortiSandbox|SharePoint Server|SMA1000|Oracle E-Business Suite|Oracle Payments' \
  -g '*sbom*' -g '*.cdx.json' -g '*.spdx.json' -g '*.md' -g '*.yaml' -g '*.yml' \
  "$WORKSPACE_ROOT" || true
```

Assessment notes:

- A manifest or lockfile hit establishes possible exposure, not execution. Correlate it with install, import, build, test, editor, endpoint, and CI history.
- No lockfile hit does not clear globally installed, dynamically fetched, cached, vendored, previously removed, or editor-managed packages.
- Vulnerability-only audits may lag malicious-package records. Compare names and resolved versions with current malware advisories as a separate control.
- Do not investigate suspected malware by importing, installing, or executing it on a normal workstation. Use the organization's isolated analysis and incident-response process.
- For security appliances, ERP, and collaboration products, verify deployed versions through vendor-supported inventory. Do not probe systems you do not own or administer.

## Copy/Paste Remediation

For a Node project with a lockfile and no evidence of compromise:

```bash
# Rebuild from a reviewed lockfile while suppressing lifecycle scripts during initial inspection.
npm ci --ignore-scripts
npm audit --audit-level=high
npm test
```

If a newly recorded malicious package was installed, imported, or executed:

1. Stop using the affected environment for credentialed development, builds, releases, and deployments.
2. Preserve relevant endpoint, process, package-manager, CI, source-control, registry, and identity logs under the incident-response policy.
3. Rebuild the workstation or runner from a known-good image rather than trusting package removal alone.
4. Restore a reviewed lockfile and use a maintainer-confirmed package and release. Recheck the live advisory before changing a production dependency.
5. Rotate credentials reachable from the affected process through the relevant account, cloud, registry, signing, or secret-manager interface. Revoke active sessions and review audit logs.
6. Rebuild and compare artifacts from reviewed source before restoring publication or deployment access.

For release workflows, GitHub Actions, OIDC, and runners:

```yaml
# Start every workflow with no token permissions; grant only what each job requires.
permissions: {}
```

- Never check out or execute untrusted pull-request code in a privileged `pull_request_target` job.
- Protect every branch and tag that can trigger a release. Require reviewed changes and environment approval for public publication.
- Pin third-party actions to reviewed commit SHAs and use dependency tooling to keep pins current.
- Separate `id-token: write`, repository writes, and package publication into minimal jobs where feasible.
- Use ephemeral isolated runners for untrusted code. Update runner binaries, images, bootstrap automation, and cached templates together.
- Validate immutable OIDC owner and repository IDs, audience, branch, reusable workflow, and environment conditions in non-production before changing production trust.

For MCP, agents, package selection, and editor extensions:

- Deny new packages, servers, tools, extensions, endpoints, and permissions by default; approve the exact publisher, repository, package, version, endpoint, and capability.
- Treat tool descriptions, package READMEs, retrieved documents, issue text, web pages, and persistent memory as untrusted data, never as authorization.
- Require human approval for credential use, external writes, package publication, deployment, destructive actions, and scope expansion.
- Bind each agent or MCP server to a dedicated least-privilege identity and narrow network destinations.
- Revoke approval when metadata, ownership, binary, endpoint, dependencies, or requested permissions change.
- Disable workspace extension recommendations and automatic task execution for untrusted repositories until reviewed.

For exploited products:

- Follow CISA-required actions and the current vendor advisory. Patch supported systems, isolate unsupported systems, and discontinue products that cannot be mitigated.
- Prioritize FortiSandbox CVE-2026-39808 and CVE-2026-25089 and SharePoint CVE-2026-58644 for July 19.
- Close SonicWall SMA1000 and SharePoint CVE-2026-56164 remediation today, and Oracle E-Business Suite CVE-2026-46817 by July 18.
- Investigate authentication, administrative, application, and network activity around affected products. Patching closes the vulnerability but does not erase prior exploitation.

## Verification

# Confirm the intended repository-only change set.
git status --short
git diff --check
```

  . || true

```

```bash
# Re-run workflow review after hardening.
if [ -d .github/workflows ]; then
  rg -n 'pull_request_target|workflow_run|id-token:[[:space:]]*write|contents:[[:space:]]*write|packages:[[:space:]]*write|npm publish|permissions:|runs-on:[[:space:]]*self-hosted|uses:' \
    .github/workflows || true
fi
```

Verify operationally:

- A clean ephemeral CI run succeeds from the reviewed commit using the updated lockfile, pinned actions, and current runner image.
- A staged release requires the intended protected branch, workflow, identity, and approval; an unauthorized non-production source cannot publish.
- Cloud federation succeeds only for the intended immutable GitHub subject and audience; a deliberately unauthorized request is denied.
- Package-registry, GitHub, cloud, identity, and signing logs show no unexplained actions after containment and credential rotation.
- MCP and agent tests demonstrate that untrusted content cannot grant permissions, add tools, change durable memory without review, or trigger external writes without approval.
- Editor inventory matches the organization allowlist and endpoint tooling reports no blocked or quarantined extension.
- Product owners record the remediated version, deployment date, exposure review, and incident-triage result for every applicable KEV item.
