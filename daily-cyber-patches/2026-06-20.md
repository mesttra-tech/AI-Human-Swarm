# Daily Cyber Patch - 2026-06-20

Mode: Public defensive guidance. No private environment data included.

## Executive Summary

- The live CISA KEV catalog is still at version 2026.06.18, with Splunk Enterprise CVE-2026-20253 due on 2026-06-21 and several June exploited-vulnerability deadlines already overdue. Patch exposed enterprise runtimes before lower-confidence ecosystem triage.
- Current supply-chain risk is centered on release trust: compromised developer identities, package-manager publish paths, GitHub Actions OIDC tokens, workflow provenance, and editor or agent plugins can make malicious releases look operationally normal.
- AI-assisted development environments need explicit trust boundaries. Treat GitHub issue text, pull requests, package metadata, MCP tool descriptions, editor settings, extension recommendations, and model outputs as untrusted until reviewed.

## Copy/Paste Assessment

Run only the checks that match your environment. These commands should not print secret values.

```bash
# Set this to your local workspace before running checks.
export WORKSPACE_ROOT="<WORKSPACE_ROOT>"
cd "$WORKSPACE_ROOT"
```

```bash
# Find common Node and Python manifests and lockfiles.
find "$WORKSPACE_ROOT" -type f \( \
  -name package.json -o \
  -name package-lock.json -o \
  -name pnpm-lock.yaml -o \
  -name yarn.lock -o \
  -name requirements.txt -o \
  -name pyproject.toml -o \
  -name pylock.toml -o \
  -name uv.lock \
\) -not -path '*/node_modules/*' -not -path '*/.venv/*' -print
```

```bash
# Review install-time package scripts without executing them.
rg -n '"(preinstall|install|postinstall|prepare)"[[:space:]]*:' \
  -g 'package.json' \
  -g '!**/node_modules/**' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Surface registry and release configuration without printing token values.
find "$WORKSPACE_ROOT" -type f \( -name .npmrc -o -name .pypirc -o -name pyproject.toml -o -name package.json \) \
  -not -path '*/node_modules/*' \
  -not -path '*/.venv/*' \
  -print
rg --files-with-matches --hidden -i '(_authToken|NPM_TOKEN|NODE_AUTH_TOKEN|PYPI_TOKEN|TWINE_PASSWORD|npm_[A-Za-z0-9]{20,}|pypi-[A-Za-z0-9]{20,})' \
  -g '.npmrc' \
  -g '.pypirc' \
  -g 'package.json' \
  -g 'pyproject.toml' \
  -g '.github/workflows/*.yml' \
  -g '.github/workflows/*.yaml' \
  -g '!**/.git/**' \
  -g '!**/node_modules/**' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Review workflows for risky triggers, OIDC minting, broad permissions, mutable actions, and untrusted interpolation.
rg -n '(pull_request_target|workflow_run|issue_comment|repository_dispatch|id-token:[[:space:]]*write|permissions:[[:space:]]*write-all|uses:[[:space:]]*[^@[:space:]]+@[^0-9a-f]|github\.event\..*(title|body|head_ref|ref|label|message|name))' \
  -g '.github/workflows/*.yml' \
  -g '.github/workflows/*.yaml' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Surface MCP, editor, and container configuration that deserves manual review in unfamiliar repos.
find "$WORKSPACE_ROOT" -type f \( \
  -name 'mcp.json' -o \
  -name 'mcp.yaml' -o \
  -path '*/.vscode/extensions.json' -o \
  -path '*/.vscode/settings.json' -o \
  -name 'devcontainer.json' -o \
  -path '*/.devcontainer/devcontainer.json' \
\) -print
```

```bash
# Pull current KEV additions for patch prioritization.
curl -fsSL https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json \
  | jq -r '.vulnerabilities | sort_by(.dateAdded) | reverse | .[] | select(.dateAdded >= "2026-06-01") | [.dateAdded,.dueDate,.cveID,.vendorProject,.product,.knownRansomwareCampaignUse] | @tsv'
```

```bash
# Look for long-running interpreter processes by executable name only after suspicious installs or extension activation.
ps -axo pid,ppid,etime,comm | rg '(node|bun|python|ruby|sh)$' || true
```

## Copy/Paste Remediation

```bash
# Node triage path when install-time compromise is suspected.
npm ci --ignore-scripts
npm audit --audit-level=high
```

```bash
# Python triage path when package compromise may affect your dependency set.
python -m pip check
python -m pip list --outdated
pip-audit || true
```

```bash
# Release-pipeline hardening checklist.
# - Prefer npm or PyPI trusted publishing over long-lived publish tokens when supported.
# - Isolate publishing to a dedicated workflow and protected environment.
# - Keep workflow and job permissions minimal, especially id-token and contents.
# - Scope OIDC trust by repository, workflow file, ref, environment, audience, and subject claims where supported.
# - Pin third-party GitHub Actions by full commit SHA.
# - Keep issue text, PR text, comments, branch names, tool output, and model output out of direct shell execution.
# - Require review before enabling self-hosted, privileged, or network-adjacent runners.
true
```

```bash
# Package install hardening checklist.
# - Use lockfiles with hashes where available.
# - Add a minimum package-age or dependency-cooldown policy for routine installs.
# - Bypass cooldowns deliberately only for verified security updates.
# - Compare registry artifacts against source tags, attestations, and expected publish workflows for critical packages.
# - Quarantine suspicious package installs and rotate affected GitHub, registry, cloud, webhook, SSH, and signing credentials through approved UIs.
true
```

```bash
# Agent, MCP, and editor hardening checklist.
# - Open unfamiliar repositories in restricted or untrusted mode first.
# - Treat MCP manifests, tool descriptions, extension recommendations, workspace settings, tasks, and devcontainers as code.
# - Review new local agents, MCP servers, extension publishers, and tool permissions before enabling them.
# - Keep agent-accessible credentials out of workspaces, dependency folders, issue text, prompts, and CI logs.
```
