# Daily Cyber Patch - 2026-07-08

Mode: Public defensive guidance. No private environment data included.

## Executive Summary

- CISA added four vulnerabilities to the Known Exploited Vulnerabilities catalog on 2026-07-07: Adobe ColdFusion CVE-2026-48282, Langflow CVE-2026-55255, Joomlack Page Builder CVE-2026-56290, and JoomShaper SP Page Builder CVE-2026-48908. All have a 2026-07-10 remediation deadline.
- Adobe confirms limited in-the-wild exploitation of CVE-2026-48282 and directs affected ColdFusion 2025 and 2023 users to Update 10 and Update 21 respectively. Langflow's maintainer advisory identifies versions before 1.9.1 as affected.
- The GitHub Advisory Database published a large batch of npm malware advisories from 2026-07-06 through research time on 2026-07-08. Advisory publication time is not package publication time or proof of compromise; reconcile manifests and lockfiles against live advisory records before acting.
- GitHub's second self-hosted-runner registration brownout for Enterprise Cloud with Data Residency is today, 2026-07-08, from 11:00 AM to 3:00 PM ET. GitHub's immutable Actions OIDC subject transition follows on 2026-07-15.
- Package, runtime, editor, MCP, and agent risks share a control problem: code or metadata that looked safe at approval time may change later or execute in a more privileged context. Pin reviewed inputs, monitor provenance and metadata drift, isolate untrusted content, and require deterministic approval at consequential tool boundaries.

## Copy/Paste Assessment

Run only checks that match an environment you are authorized to review. These commands list filenames, package references, workflow settings, or executable names; they are not intended to print secret values.

```bash
# Set this to the workspace you are authorized to review.
export WORKSPACE_ROOT="<WORKSPACE_ROOT>"
cd "$WORKSPACE_ROOT"
```

```bash
# Pull current CISA KEV data for defensive prioritization.
curl -fsSL https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json -o kev.json
jq -r '.catalogVersion, .dateReleased, (.vulnerabilities | sort_by(.dateAdded) | reverse | .[0:20][] | [.dateAdded,.dueDate,.cveID,.vendorProject,.product] | @tsv)' kev.json
```

```bash
# Find package manifests, lockfiles, registry configs, native-build metadata, and Python startup hooks.
find "$WORKSPACE_ROOT" -type f \( \
  -name package.json -o -name package-lock.json -o -name npm-shrinkwrap.json -o \
  -name pnpm-lock.yaml -o -name yarn.lock -o -name requirements.txt -o \
  -name pyproject.toml -o -name pylock.toml -o -name uv.lock -o \
  -name binding.gyp -o -name extconf.rb -o -name '*.pth' -o \
  -name .npmrc -o -name .pypirc \
\) -not -path '*/node_modules/*' -not -path '*/.venv/*' -print
```

```bash
# Review declared Node lifecycle scripts without executing them.
rg -n '"(preinstall|install|postinstall|prepare)"[[:space:]]*:' \
  -g 'package.json' -g '!**/node_modules/**' "$WORKSPACE_ROOT" || true
```

```bash
# Identify files that appear to contain registry or automation credentials without printing contents.
rg --files-with-matches --hidden -i '(_authToken|NPM_TOKEN|NODE_AUTH_TOKEN|PYPI_TOKEN|TWINE_PASSWORD)' \
  -g '.npmrc' -g '.pypirc' -g 'package.json' -g 'pyproject.toml' \
  -g '.github/workflows/*.yml' -g '.github/workflows/*.yaml' \
  -g '!**/.git/**' -g '!**/node_modules/**' "$WORKSPACE_ROOT" || true
```

```bash
# Review workflow trust boundaries, caches, OIDC, broad permissions, and unsafe interpolation surfaces.
rg -n '(pull_request_target|workflow_run|issue_comment|repository_dispatch|actions/cache|id-token:[[:space:]]*write|permissions:[[:space:]]*write-all|secrets:[[:space:]]*inherit|github\.event\..*(title|body|head_ref|ref|label|message|name))' \
  -g '.github/workflows/*.yml' -g '.github/workflows/*.yaml' "$WORKSPACE_ROOT" || true
```

```bash
# Find third-party Actions that are not pinned to a full 40-character commit SHA.
rg -n 'uses:[[:space:]]*[^[:space:]]+/[^[:space:]@]+@[^#[:space:]]+' \
  -g '.github/workflows/*.yml' -g '.github/workflows/*.yaml' "$WORKSPACE_ROOT" \
  | rg -v '@[0-9a-f]{40}([[:space:]#]|$)' || true
```

```bash
# Surface agent, MCP, editor, plugin, task, hook, memory, and devcontainer configuration.
find "$WORKSPACE_ROOT" -type f \( \
  -name 'mcp.json' -o -name 'mcp.yaml' -o -name 'mcp.toml' -o \
  -name 'AGENTS.md' -o -path '*/.claude/settings.json' -o \
  -path '*/.vscode/extensions.json' -o -path '*/.vscode/settings.json' -o \
  -path '*/.vscode/tasks.json' -o -path '*/.cursor/rules/*' -o \
  -path '*/.github/copilot-instructions.md' -o -name 'managed-settings.json' -o \
  -name 'devcontainer.json' \
\) -print
```

```bash
# After a suspicious install, import, extension activation, or agent run, list long-running interpreters by executable name only.
ps -axo pid,ppid,etime,comm | rg '(node|bun|python|python3|java|ruby|sh|bash)$' || true
```

- This patch is generic public guidance, not a scan of any private workspace, device, runner, cloud account, registry account, web server, CMS, editor profile, or agent environment.
- No live credentials, private logs, private package metadata, customer systems, browser sessions, MCP servers, agent sessions, or cloud trust policies were accessed.
- The four new KEV actions are not applicable where the named products are absent. Affected versions and fixes must be confirmed against current CISA and vendor advisories.
- npm, PyPI, GitHub Actions, OIDC, self-hosted-runner, MCP, agent-memory, browser-tool, and editor-extension checks apply only where those technologies are used.
- The 2026-07-08 runner brownout applies to GitHub Enterprise Cloud with Data Residency. GitHub publishes a separate later schedule for standard Enterprise Cloud; GitHub Enterprise Server is not currently affected.
- GitHub's immutable OIDC subject change applies automatically to new repositories and repository renames after 2026-07-15; existing repositories require explicit opt-in.
- GitHub malware-advisory publication dates do not by themselves establish when a package was uploaded, installed, or executed. Local exposure requires manifest, lockfile, registry, cache, artifact, and install-timeline evidence.
- Red Hat states its affected packages were not part of released Red Hat products or managed cloud services and that no customer action is required. The incident remains a general developer-tooling lesson, not a blanket Red Hat exposure claim.
- Campaign and package reports can change as investigations mature. Names and versions must be confirmed against maintainer, registry, marketplace, OSV, or GitHub Security Advisory records before remediation.
- Threat reports describe observed patterns and do not establish compromise in a specific environment.
