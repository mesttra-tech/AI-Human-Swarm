# Daily Cyber Patch - 2026-07-24

Mode: Public defensive guidance. No private environment data included.

## Executive Summary

- CISA's Known Exploited Vulnerabilities catalog advanced to version `2026.07.23`. No newer product set was added after the July 22 SmartConsole and SharePoint entries. WordPress CVE-2026-63030, Langflow CVE-2026-0770, and DD-WRT CVE-2021-27137 are due today; Check Point SmartConsole CVE-2026-16232 and Microsoft SharePoint CVE-2026-50522 are due July 25.
- Ten npm malware advisories were published after the prior completed run, including `eth-slint`, `eth-base`, `chai-as-stringify`, `yuinpm`, `svgcraft-core`, and related packages. No matching PyPI malware advisories appeared in the same public query window. Treat the package names as assessment triggers, not proof of installation, execution, one campaign, or complete ecosystem coverage.
- Today is GitHub's final configuration-plus-runtime brownout for outdated self-hosted runners in Enterprise Cloud with Data Residency, ahead of July 31 enforcement. New repositories and repositories renamed or transferred after July 15 use immutable OIDC subject claims, so cloud trust policies should be checked before release jobs fail or become over-broad.
- Package and developer-tool defenses must cover install hooks, implicit native builds, imports, CLIs, tests, editors, agents, runners, and delayed activation. The Jscrambler incident demonstrated a shift from install-time execution to runtime execution, while Red Hat's completed investigation connected a malicious editor extension to package publication and workspace configuration changes.

## Copy/Paste Assessment

Run only checks that match systems you own or administer. These commands list files, configuration locations, package identities, and workflow controls; they do not print credential values.

```bash
# Set this placeholder to the workspace you are authorized to assess.
export WORKSPACE_ROOT="<WORKSPACE_ROOT>"
cd "$WORKSPACE_ROOT"
```

```bash
# Locate dependency manifests and lockfiles without traversing installed dependencies.
find "$WORKSPACE_ROOT" -type f \( \
  -name package.json -o \
  -name package-lock.json -o \
  -name pnpm-lock.yaml -o \
  -name yarn.lock -o \
  -name requirements.txt -o \
  -name pyproject.toml -o \
  -name uv.lock -o \
  -name poetry.lock \
\) -not -path '*/node_modules/*' -not -path '*/.venv/*' -print
```

```bash
# Review representative identities from current public malware advisories.
# A hit is an assessment trigger; do not install, import, restore, or execute it.
rg -n '(^|[\"/ ])(eth-slint|eth-base|chai-as-stringify|yuinpm|svgcraft-core|eth-codergen)([\"/@ <]|$)' \
  -g 'package.json' -g 'package-lock.json' -g 'pnpm-lock.yaml' -g 'yarn.lock' \
  -g 'requirements.txt' -g 'pyproject.toml' -g 'uv.lock' -g 'poetry.lock' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Review explicit install-time scripts. Their absence does not prove runtime safety.
rg -n '"(preinstall|install|postinstall|prepare)"[[:space:]]*:' \
  -g 'package.json' -g '!**/node_modules/**' \
  "$WORKSPACE_ROOT" || true

# Identify native-build and registry-auth configuration without printing values.
find "$WORKSPACE_ROOT" -type f \( \
  -name binding.gyp -o \
  -name .npmrc -o \
  -name pip.conf -o \
  -name pyproject.toml \
\) -not -path '*/node_modules/*' -not -path '*/.venv/*' -not -path '*/.git/*' -print

rg --files-with-matches --hidden -i '(_authToken|NPM_TOKEN|npm_[A-Za-z0-9]{20,}|index-url|extra-index-url)' \
  -g '.npmrc' -g 'pip.conf' -g 'pyproject.toml' \
  -g '!**/.git/**' -g '!**/node_modules/**' -g '!**/.venv/**' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Review workflow triggers, privileges, cache/artifact handoffs, runner type, and action references.
if [ -d "$WORKSPACE_ROOT/.github/workflows" ]; then
  rg -n 'pull_request_target|workflow_run|issue_comment|workflow_dispatch|id-token:[[:space:]]*write|contents:[[:space:]]*write|packages:[[:space:]]*write|npm publish|pypa/gh-action-pypi-publish|permissions:|runs-on:[[:space:]]*self-hosted|actions/(checkout|cache|upload-artifact|download-artifact)@|uses:' \
    "$WORKSPACE_ROOT/.github/workflows" || true
fi
```

```bash
# Inventory repository-scoped agent, MCP, editor, and startup configuration by filename.
find "$WORKSPACE_ROOT" -type f \( \
  -name 'mcp.json' -o \
  -name '.mcp.json' -o \
  -name 'settings.json' -o \
  -name 'extensions.json' -o \
  -name 'tasks.json' -o \
  -name 'launch.json' -o \
  -name 'AGENTS.md' \
\) -not -path '*/node_modules/*' -not -path '*/.git/*' -print

# Review endpoints, automatic approval, allowed tools, extension recommendations, tasks, and executable paths.
rg -n 'mcpServers|serverUrl|autoApprove|allowedTools|recommendations|command|executablePath' \
  -g '*.json' -g '*.jsonc' -g '*.toml' -g '*.yaml' -g '*.yml' \
  -g '!**/node_modules/**' -g '!**/.git/**' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Search owned inventories and documentation for the current KEV products.
rg -n -i 'SmartConsole|SharePoint Server|WordPress|Langflow|DD-WRT' \
  -g '*sbom*' -g '*.cdx.json' -g '*.spdx.json' -g '*.md' -g '*.yaml' -g '*.yml' \
  "$WORKSPACE_ROOT" || true
```

Assessment notes:

- A manifest or lockfile match establishes possible exposure, not execution. Correlate it with install, build, import, test, editor, endpoint, runner, and release history.
- No lockfile match does not clear globally installed, dynamically fetched, cached, vendored, previously removed, editor-managed, or agent-managed components.
- Current advisory publication volume includes related batches and test-like package names. Do not infer one actor, one campaign, exposure, execution, or equivalent severity from the count.
- Do not investigate suspected malware by installing, importing, restoring, or executing it on a normal workstation. Use the organization's isolated analysis and incident-response process.
- An install-script block does not stop registry configuration processing, implicit native builds, package imports, CLIs, tests, plugins, editor activation, agent tools, or later execution.
- Verify affected product versions through vendor-supported inventory. Do not probe systems you do not own or administer.

## Copy/Paste Remediation

For a Node project with a reviewed lockfile and no evidence of compromise:

```bash
# Rebuild from the reviewed lockfile while suppressing lifecycle scripts during initial inspection.
npm ci --ignore-scripts
npm audit --audit-level=high
npm test
```

Package and registry controls:

- Move toward npm v12's default-deny install model. Review and approve only necessary dependency scripts, native builds, Git dependencies, and remote dependencies.
- Use a routine release cooldown so brand-new package versions do not enter production immediately. Keep security-update handling separate so urgent fixes are not delayed.
- Pin direct and transitive dependencies with reviewed lockfiles. Verify hashes or attestations where supported, but treat provenance as origin evidence rather than proof that code is safe.
- Prefer short-lived trusted publishing over long-lived registry tokens. Protect the workflow, environment, branch, and identity that can invoke the trusted publisher.
- Bind registry credentials to exact intended hosts and scopes. Treat new registry hosts, publisher changes, old-version file additions, and unexpected install or runtime permissions as security-review events.

If a malicious package or extension was installed, imported, restored, or executed:

1. Stop using the affected environment for credentialed development, builds, releases, and deployments.
2. Preserve relevant endpoint, process, editor, package-manager, CI, source-control, registry, identity, and signing logs under the incident-response policy.
3. Rebuild the workstation or runner from a known-good image rather than trusting package or extension removal alone.
4. Restore reviewed lockfiles, extensions, MCP servers, agent tools, and workspace configuration from known-good sources.
5. Rotate credentials reachable from the affected process through the relevant account, cloud, registry, signing, or secret-manager interface. Revoke active sessions and review audit logs.
6. Rebuild and compare release artifacts from reviewed source before restoring publication or deployment access.

For GitHub Actions, OIDC, caches, and runners:

```yaml
# Start every workflow with no token permissions; grant only what each job requires.
permissions: {}
```

- Never execute untrusted pull-request code in a privileged `pull_request_target`, `workflow_run`, comment-triggered, or release job.
- Separate repository writes, `id-token: write`, cache writes, artifact promotion, signing, and package publication into minimal reviewed jobs.
- Pin third-party actions to reviewed commit SHAs and use dependency tooling to keep those pins current.
- Protect every branch, tag, environment, and reusable workflow that can publish or deploy. Require review for production environments.
- Validate immutable owner and repository IDs, audience, branch, environment, and reusable-workflow conditions in cloud trust policies. Remove obsolete name-only subjects after a verified migration.
- Use ephemeral isolated runners for untrusted code. Update runner binaries, base images, bootstrap automation, and cached templates together.
- Treat caches and artifacts crossing trust levels as untrusted inputs. Verify origin and content before privileged consumption.

For MCP, agents, and editor extensions:

- Deny new packages, servers, tools, extensions, endpoints, and permissions by default. Approve the exact publisher, repository, version, endpoint, metadata, and capability.
- Treat tool descriptions, package documentation, retrieved files, issue text, web pages, code comments, and durable memory as untrusted data, never as authorization.
- Keep unfamiliar workspaces in Restricted Mode. Review workspace tasks, settings, extension recommendations, MCP configuration, and executable paths before granting trust.
- Revoke approval whenever ownership, binary, dependencies, endpoint, tool description, schema, or requested permissions change.
- Bind each agent or MCP server to a dedicated least-privilege identity and narrow network destinations.
- Require human approval for credential use, external writes, publication, deployment, destructive actions, and scope expansion.
- Authenticate local control planes, validate origins, bind network services to the narrowest interface, and isolate browsing or untrusted content from privileged tool execution.

For exploited products:

- Follow CISA-required actions and current vendor advisories. Patch supported systems, isolate unsupported systems, and discontinue products that cannot be mitigated.
- Treat WordPress CVE-2026-63030, Langflow CVE-2026-0770, and DD-WRT CVE-2021-27137 as due July 24.
- Treat Check Point SmartConsole CVE-2026-16232 and SharePoint CVE-2026-50522 as due July 25.
- WordPress owners should also apply a release that fixes CVE-2026-60137; WordPress identifies 7.0.2, 6.9.5, and 6.8.6 applicability in its release notice.
- Investigate relevant authentication, administrative, application, endpoint, and network activity. Patching closes the vulnerability but does not erase prior exploitation.

Verify operationally:

- A clean ephemeral CI run succeeds from the reviewed commit using reviewed lockfiles, pinned actions, and a current runner image.
- A staged release requires the intended protected branch, workflow, immutable identity, and approval; an unauthorized non-production source cannot publish.
- Cloud federation succeeds only for the intended immutable GitHub subject and audience; a deliberately unauthorized request is denied.
- Package-registry, GitHub, cloud, identity, and signing logs show no unexplained actions after containment and credential rotation.
- MCP and agent tests demonstrate that untrusted content cannot add tools, change permissions, alter durable memory without review, reach privileged control planes, or trigger external writes without approval.
- Editor inventory matches the approved publisher and version list, and unfamiliar repositories remain restricted until configuration review is complete.
- Product owners record remediated version, deployment date, exposure review, and incident-triage result for every applicable KEV item.

- The MCP and WebMCP studies are research evidence, not proof that every client or deployment is vulnerable in the same way.
