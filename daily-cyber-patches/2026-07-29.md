# Daily Cyber Patch - 2026-07-29

Mode: Public defensive guidance. No private environment data included.

## Executive Summary

- Treat the July 27-29 malware-advisory burst as a dependency-matching event, not a count of newly compromised projects. GitHub expanded Dependabot malware coverage by ingesting OpenSSF malicious-package records on July 28; the public API returned 2,332 npm records covering 2,313 unique package names and seven PyPI records after the prior completed patch cutoff.
- Reconcile manifests, lockfiles, caches, images, and artifacts against the expanded advisory feed. The newly visible records include npm packages associated with Mini Shai-Hulud and PyPI packages with install-, import-, native-module-, and startup-file activation paths.
- Adopt the new platform controls without treating them as complete prevention. npm now scans new packages before they become installable, and GitHub now holds some potentially malicious workflow runs in public repositories for authenticated approval. Neither control replaces reviewed lockfiles, package cooldowns, least-privilege workflows, isolated runners, or incident response after execution.
- CISA KEV catalog version `2026.07.27` added Arista VeloCloud Orchestrator CVE-2026-16812, due July 30, and Fortinet FortiOS CVE-2025-68686, due August 10. KNX CVE-2023-4346 is due today, and WordPress CVE-2026-60137 is due August 4.

## Copy/Paste Assessment

Run only the checks that match your environment. These commands should not print secret values.

```bash
# Set this to your local workspace before running checks.
export WORKSPACE_ROOT="<WORKSPACE_ROOT>"
cd "$WORKSPACE_ROOT"
```

```bash
# Find package manifests, lockfiles, and repository-controlled package-manager configuration.
find "$WORKSPACE_ROOT" -type f \( \
  -name package.json -o -name package-lock.json -o \
  -name pnpm-lock.yaml -o -name pnpm-workspace.yaml -o \
  -name yarn.lock -o -name requirements.txt -o \
  -name pyproject.toml -o -name poetry.lock -o \
  -name uv.lock -o -name .npmrc \
\) -not -path '*/node_modules/*' -not -path '*/.venv/*' -print
```

```bash
# Review package lifecycle hooks and non-registry dependency sources without running them.
rg -n '"(preinstall|install|postinstall|prepare)"[[:space:]]*:' \
  -g 'package.json' -g '!**/node_modules/**' "$WORKSPACE_ROOT" || true

rg -n '"[^"]+"[[:space:]]*:[[:space:]]*"(git\\+|github:|gitlab:|https?://|file:)' \
  -g 'package.json' -g '!**/node_modules/**' "$WORKSPACE_ROOT" || true
```

```bash
# Match representative package names from current public advisories without installing them.
# This is not a complete denylist; use the live advisory feed for complete matching.
rg -n -i '(^|["/ ])(@antv/mcp-server-antv|mcp-echarts|cfgzen|karpatkit)(["/@ <]|$)' \
  -g 'package.json' -g 'package-lock.json' -g 'npm-shrinkwrap.json' \
  -g 'pnpm-lock.yaml' -g 'yarn.lock' -g 'requirements*.txt' \
  -g 'pyproject.toml' -g 'poetry.lock' -g 'uv.lock' \
  "$WORKSPACE_ROOT" || true
```

Representative affected versions from public advisories:

- `@antv/mcp-server-antv`: `0.2.8` and `0.3.8`
- `mcp-echarts`: `0.8.1` and `0.9.1`
- `cfgzen`: `1.0.0` through `1.0.6`
- `karpatkit`: `2.1.0` and `2.1.1`

```bash
# Inventory Python startup files and native modules by filename only.
# Unexpected files require provenance review; presence alone does not prove malware.
find "$WORKSPACE_ROOT" -type f \( \
  -name '*.pth' -o -name '*.so' -o -name '*.pyd' -o -name '*.dylib' \
\) -not -path '*/.git/*' -print
```

```bash
# Review workflow triggers, privileges, runner types, cache/artifact handoffs, and action references.
if [ -d "$WORKSPACE_ROOT/.github/workflows" ]; then
  rg -n 'pull_request_target|workflow_run|issue_comment|workflow_dispatch|id-token:[[:space:]]*write|contents:[[:space:]]*write|packages:[[:space:]]*write|permissions:|runs-on:[[:space:]]*self-hosted|actions/(checkout|cache|upload-artifact|download-artifact)@|uses:' \
    "$WORKSPACE_ROOT/.github/workflows" || true
fi
```

For a workflow held by GitHub, review before approval:

- Triggering actor, event, source branch, commit, and repository ownership.
- Every workflow-file and action-reference change between the trusted base and triggering commit.
- Token permissions, secrets, environments, `id-token: write`, cache writes, artifact promotion, and runner labels.
- Whether any preceding or reusable workflow already processed untrusted input with higher privilege.

```bash
# Inventory repository-scoped editor, MCP, agent, task, and hook configuration by filename.
find "$WORKSPACE_ROOT" -type f \( \
  -name mcp.json -o -name extensions.json -o -name settings.json -o \

  -name '*.code-workspace' \

rg -n -i 'auto.?approve|allowed.?tools|trusted|restricted|sandbox|publisher|extension|mcp|endpoint|command|executable|network|memory|hook' \
  -g 'mcp.json' -g 'extensions.json' -g 'settings.json' -g 'tasks.json' \
  -g 'hooks.json' -g '*.code-workspace' \
  "$WORKSPACE_ROOT" || true
```

Assessment cautions:

- Do not infer one actor, one campaign, current installation, execution, or equal severity from advisory counts, similar names, or a concentrated publication timestamp.
- The July 27-29 advisory counts include a catalog-ingestion expansion. Advisory publication time is not package upload, installation, execution, or compromise time.
- Do not investigate suspected malware by installing, importing, restoring, or executing it on a normal workstation.
- Install-script blocking does not stop package imports, CLIs, tests, plugins, editor activation, MCP startup, Python `.pth` processing, native modules, or later execution.
- npm publish-time scanning, marketplace badges, provenance, signatures, and OIDC attest selected trust properties; none proves that source, workflows, dependencies, artifacts, or behavior are benign.
- Verify affected product versions through vendor-supported inventory. Do not probe systems you do not own or administer.

## Copy/Paste Remediation

For a Node project with a reviewed lockfile and no evidence of compromise:

```bash
# Rebuild from the reviewed lockfile while suppressing lifecycle scripts during initial inspection.
npm ci --ignore-scripts
npm audit --audit-level=high
npm test
```

For a Python project with a reviewed lockfile and no evidence of compromise:

```bash
# Create a clean environment, then use the project's approved lockfile workflow.
python -m venv .venv-review
. .venv-review/bin/activate
python -m pip install --upgrade pip
python -m pip check
python -m pip list
```

Do not reinstall a suspected package merely to inspect it. Use the package index, advisory record, retained artifact, or an isolated malware-analysis process approved by your incident-response team.

Package and registry controls:

- Enable Dependabot malware alerts or equivalent package-malware matching across supported ecosystems. Deduplicate advisory bursts before escalation and preserve the package name, ecosystem, version, source, and publication time.
- Allow for npm’s publish-time scanning delay in release automation. Do not bypass the hold by changing registries or dependency sources.
- Use a routine release cooldown so brand-new package versions do not enter production immediately. Keep urgent security updates on a separately reviewed path.
- Prefer npm v12’s default-deny behavior for dependency scripts, native builds, Git dependencies, and remote dependencies. Approve only the exact packages and sources required by the build.
- Pin direct and transitive dependencies with reviewed lockfiles and hashes where supported. Re-review changes in publisher, ownership, registry host, resolved file set, permissions, dependencies, lifecycle hooks, native modules, and runtime behavior.
- Prefer short-lived trusted publishing over long-lived registry tokens. Protect the workflow, environment, branch, repository identity, and human approval that can invoke the publisher.

If a malicious package or extension was installed, imported, restored, or executed:

1. Stop using the affected environment for credentialed development, builds, releases, and deployments.
2. Isolate the environment and preserve relevant endpoint, process, editor, package-manager, CI, source-control, registry, identity, agent, and signing logs under the incident-response policy.
3. Rebuild the workstation or runner from a known-good image rather than trusting package or extension removal alone.
4. Restore reviewed lockfiles, virtual environments, extensions, MCP servers, agent tools, workflow files, caches, artifacts, startup files, and hooks from known-good sources.
5. Rotate credentials reachable from the affected process through the relevant account, cloud, registry, signing, or secret-manager interface. Revoke active sessions and review audit logs.
6. Rebuild and compare release artifacts from reviewed source before restoring publication or deployment access.

For GitHub Actions, OIDC, caches, and runners:

```yaml
# Start every workflow with no token permissions; grant only what each job requires.
permissions: {}
```

- Treat a held run as a security review queue, not a routine confirmation prompt. Reject it if the actor, commit, workflow changes, permissions, action pins, or runner target cannot be explained.
- Never execute untrusted pull-request code in a privileged `pull_request_target`, `workflow_run`, comment-triggered, release, or publication job.
- Separate repository writes, `id-token: write`, cache writes, artifact promotion, signing, and publication into minimal reviewed jobs.
- Pin third-party actions to reviewed full commit SHAs and use dependency tooling to keep those pins current.
- Protect every branch, tag, environment, and reusable workflow that can publish or deploy. Require review for production environments.
- Validate immutable owner and repository IDs, audience, branch, environment, and reusable-workflow conditions in cloud trust policies.
- Use ephemeral isolated runners for untrusted code. Update runner binaries, base images, bootstrap automation, and cached templates together. GitHub Enterprise Cloud with Data Residency reaches full runner-version enforcement on July 31.
- Treat caches and artifacts crossing trust levels as untrusted inputs. Verify their origin and content before privileged consumption.

For MCP, agents, and editor extensions:

- Upgrade GitHub MCP Server to `1.1.0` or later where applicable. Keep local servers bound to the narrowest interface; require authentication for network access; rate-limit, supervise, and isolate the process.
- Deny new packages, servers, tools, extensions, endpoints, and permissions by default. Approve the exact publisher, repository, version, endpoint, tool metadata, and capability.
- Treat tool descriptions, parameter schemas, returned content, package documentation, retrieved files, issue text, web pages, code comments, workspace rules, and durable memory as untrusted data, never authorization.
- Open unfamiliar workspaces in Restricted Mode. Enable agent and local-MCP sandboxing where supported; restrict network domains and extension-contributed tools.
- Keep tool auto-approval scoped to the session. Require manual approval for terminal execution, network fetches, credential use, external writes, publication, deployment, destructive actions, and scope expansion.
- Revoke approval whenever ownership, binary, dependencies, endpoint, tool description, schema, requested permissions, hooks, or durable-memory behavior changes.
- Bind each agent or MCP server to a dedicated least-privilege identity. Validate OAuth token issuer, audience, resource, scope, expiry, and client consent; do not pass tokens through to downstream services.

For exploited products:

- Follow CISA-required actions and current vendor advisories. Patch supported systems, isolate unsupported or unmitigated systems, and discontinue products that cannot be secured.
- Close the KNX CVE-2023-4346 deadline today where applicable.
- Prioritize Arista VeloCloud Orchestrator CVE-2026-16812 before July 30, WordPress CVE-2026-60137 before August 4, and Fortinet FortiOS CVE-2025-68686 before August 10.
- Investigate relevant authentication, administrative, application, endpoint, and network activity where exposure existed. Patching closes the vulnerability but does not erase prior exploitation.

## Verification

```bash
# Confirm the intended repository-only change set.
git status --short
git diff --check
```

```bash
# Confirm representative package identities are absent after remediation.
rg -n -i '(^|["/ ])(@antv/mcp-server-antv|mcp-echarts|cfgzen|karpatkit)(["/@ <]|$)' \
  -g 'package.json' -g 'package-lock.json' -g 'npm-shrinkwrap.json' \

  -g 'pyproject.toml' -g 'poetry.lock' -g 'uv.lock' \
  . || true
```

Verify operationally:

- Dependency tooling matches reviewed lockfiles against the current expanded malware-advisory feed, and advisory bursts are deduplicated without losing package/version matches.
- A clean ephemeral CI run succeeds from the reviewed commit using reviewed lockfiles, pinned actions, and a current runner image.
- A deliberately untrusted or unexplained workflow remains held or denied; it cannot reach secrets, OIDC, write tokens, privileged caches, protected artifacts, or persistent runners.
- A staged release requires the intended protected branch, workflow, immutable identity, and approval; an unauthorized source cannot publish.
- Cloud federation succeeds only for the intended immutable GitHub subject and audience; a deliberately unauthorized request is denied.
- Package-registry, GitHub, cloud, identity, endpoint, and signing logs show no unexplained actions after containment and credential rotation.
- MCP and agent tests demonstrate that malformed requests do not terminate the service and that untrusted content cannot add tools, change permissions, alter durable memory without review, or trigger external writes without approval.
- Editor inventory matches the approved publisher and version list, and unfamiliar repositories remain restricted until configuration review is complete.
- Product owners record remediated version, deployment date, exposure review, and incident-triage result for every applicable KEV item.
