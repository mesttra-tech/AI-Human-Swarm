# Daily Cyber Patch - 2026-07-16

Mode: Public defensive guidance. No private environment data included.

## Executive Summary

- Treat installation or execution of the affected AsyncAPI npm releases as a potential developer-workstation or CI compromise. The reported code activates when the package is imported, not through an install hook, so `--ignore-scripts` alone is not a complete control.
- Review release workflows as production trust boundaries. The AsyncAPI releases were reportedly produced by the legitimate GitHub Actions OIDC trusted-publishing path and carried valid provenance; provenance establishes build origin, but cannot prove that the source branch or workflow was trustworthy.
- CISA added Oracle E-Business Suite CVE-2026-46817 and KNX Protocol CVE-2023-4346 to the Known Exploited Vulnerabilities catalog on July 15. Oracle E-Business Suite remediation is due July 18, while the July 14 SonicWall and SharePoint additions are due July 17.
- GitHub's immutable Actions OIDC subject format is now active for new repositories and for repositories renamed or transferred after July 15. Separately, unsupported Data Residency self-hosted runners face another registration brownout on July 17.
- Keep MCP servers, agents, package managers, and editor extensions behind explicit allowlists, least-privilege identities, immutable configuration review, and human approval for consequential actions. A newly published npm malware record using an MCP-themed package name reinforces that agent-tool branding is not evidence of trust.

## Copy/Paste Assessment

Run only checks that match systems you own or administer. These commands enumerate names and configuration locations; they do not print credential values.

```bash
# Set this placeholder to the workspace you are authorized to assess.
export WORKSPACE_ROOT="<WORKSPACE_ROOT>"
cd "$WORKSPACE_ROOT"
```

```bash
# Locate dependency manifests and lockfiles without traversing installed dependencies.
find "$WORKSPACE_ROOT" -type f \( \
  -name package.json -o \
  -name package-lock.json -o \
  -name pnpm-lock.yaml -o \
  -name yarn.lock -o \
  -name requirements.txt -o \
  -name pyproject.toml -o \
  -name uv.lock -o \
  -name poetry.lock -o \
  -name go.mod -o \
  -name go.sum \
\) -not -path '*/node_modules/*' -not -path '*/.venv/*' -print
```

```bash
# Check resolved Node trees for the affected AsyncAPI package names.
npm ls @asyncapi/generator @asyncapi/generator-helpers @asyncapi/generator-components @asyncapi/specs --all || true

# Review lockfiles for the five releases named in public incident reports.
rg -n '@asyncapi/(generator|generator-helpers|generator-components|specs)|3\.3\.1|1\.1\.1|0\.7\.1|6\.11\.2-alpha\.1|6\.11\.2' \
  -g 'package-lock.json' -g 'pnpm-lock.yaml' -g 'yarn.lock' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Review manifests for newly published npm and PyPI malware names without installing them.
rg -n 'claude-token-tracker-mcp|fflask' \
  -g 'package.json' -g 'package-lock.json' -g 'pnpm-lock.yaml' -g 'yarn.lock' \
  -g 'requirements*.txt' -g 'pyproject.toml' -g 'uv.lock' -g 'poetry.lock' \
  "$WORKSPACE_ROOT" || true

# Review install-time scripts. Their absence does not prove a package is safe at runtime.
rg -n '"(preinstall|install|postinstall|prepare)"[[:space:]]*:' \
  -g 'package.json' -g '!**/node_modules/**' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Identify registry-auth files by filename, and report only files containing auth markers.
find "$WORKSPACE_ROOT" -name .npmrc -type f -not -path '*/node_modules/*' -print
rg --files-with-matches --hidden -i '(_authToken|NPM_TOKEN|npm_[A-Za-z0-9]{20,})' \
  -g '.npmrc' -g '!**/.git/**' -g '!**/node_modules/**' \
  "$WORKSPACE_ROOT" || true
```

```bash
# Review workflow triggers, identity permissions, release paths, runner type, and action references.
if [ -d "$WORKSPACE_ROOT/.github/workflows" ]; then
  rg -n 'pull_request_target|workflow_run|id-token:[[:space:]]*write|contents:[[:space:]]*write|packages:[[:space:]]*write|npm publish|npm stage|permissions:|runs-on:[[:space:]]*self-hosted|uses:' \
    "$WORKSPACE_ROOT/.github/workflows" || true
fi
```

```bash

find "$WORKSPACE_ROOT" -type f \( \
  -name 'mcp.json' -o \
```

Assessment notes:

- A lockfile hit establishes possible exposure, not execution. Correlate it with package-install, package-import, build, endpoint, and CI history.
- No lockfile hit does not clear globally installed, dynamically fetched, cached, vendored, previously removed, or editor-managed packages.
- `npm audit` and Python vulnerability scanners primarily identify known vulnerabilities. Compare package names and versions with malware advisories as a separate control.
- A provenance record should be reviewed together with the exact source commit, protected branch, workflow, event, actor, and required approvals.
- Do not investigate suspected malware by importing, installing, or executing it on a normal workstation. Use the organization's isolated analysis and incident-response process.
- For network, identity, ERP, and collaboration products, verify the deployed version through the vendor-supported inventory path. Do not probe systems you do not own or administer.

## Copy/Paste Remediation

For a Node project with a lockfile and no evidence of compromise:

```bash
# Rebuild from the reviewed lockfile while suppressing lifecycle scripts during initial inspection.
npm ci --ignore-scripts
npm audit --audit-level=high
npm test
```

For affected AsyncAPI releases:

1. Stop using the affected environment for builds, releases, deployments, or credentialed development.
2. Preserve relevant endpoint, process, package-manager, CI, source-control, registry, and identity logs under the incident-response policy.
3. Rebuild the workstation or runner from a known-good image rather than trusting package removal alone.
4. Move to a maintainer-confirmed clean package release or restore the last verified safe lockfile. Recheck the current advisory before changing a production dependency.
5. Rotate credentials that were reachable from the affected process through the relevant account, cloud, registry, signing, or secret-manager interface. Revoke active sessions and review audit logs for unauthorized actions.
6. Rebuild and compare release artifacts from reviewed source before restoring publication or deployment access.

For release workflows, GitHub Actions, and OIDC:

```yaml
# Start every workflow with no token permissions; grant only the permissions each job requires.
permissions: {}
```

- Never check out or execute untrusted pull-request code in a privileged `pull_request_target` job.
- Protect every branch and tag that can trigger a release. Require reviewed changes, signed or verified identities where appropriate, and environment approval for public publication.
- Pin third-party actions to reviewed commit SHAs and use dependency tooling to keep pins current.
- Keep `id-token: write`, repository writes, and package publication on separate minimal jobs where feasible.
- Prefer npm trusted publishing over long-lived tokens, but use stage-only publishing and maintainer approval when the registry and workflow support it.
- Treat provenance as evidence to investigate, not an automatic allow decision. Validate the source commit, workflow, triggering event, actor, and review state.
- Update the cloud trust policy before changing GitHub OIDC subject configuration. Test in non-production, including a deliberately unauthorized request.
- Use ephemeral isolated runners for untrusted code. Update runner binaries, base images, bootstrap automation, and cached templates together.

For MCP, agents, package selection, and editor extensions:

- Deny new packages, servers, tools, extensions, and permissions by default; approve the exact publisher, repository, package, version, endpoint, and capability.
- Treat tool descriptions, package READMEs, retrieved documents, issue text, web pages, and persistent memory as untrusted data, never as authorization.
- Require human approval for credential use, external writes, package publication, deployment, destructive actions, and scope expansion.
- Bind each agent or MCP server to a dedicated least-privilege identity and narrow network destinations. Do not share a developer's broad session by default.
- Record and review tool-definition, server-endpoint, extension-binary, dependency, and permission changes. Revoke approval when metadata or ownership changes.
- Disable workspace extension recommendations and automatic task execution for untrusted repositories until reviewed.

For exploited products:

- Follow CISA-required actions and the current vendor advisory. Patch supported systems, isolate unsupported systems, and remove products that cannot be remediated.
- Prioritize Oracle E-Business Suite CVE-2026-46817 for the July 18 deadline, and the SonicWall SMA1000 and SharePoint Server additions for July 17.
- Inventory KNX Protocol Connection Authorization Option 1 implementations and coordinate vendor mitigations before July 29.
- Investigate identity, administrative, and application activity around affected products. Patching closes the vulnerability but does not erase prior exploitation.

Verify operationally:

- A clean ephemeral CI run succeeds from the reviewed commit using the updated lockfile, pinned actions, and current runner image.
- A staged or test package release requires the intended protected branch, workflow, identity, and approval; an unauthorized non-production source cannot publish.
- Cloud federation succeeds only for the intended immutable GitHub subject, audience, branch, reusable workflow, and protected environment; a deliberately unauthorized request is denied.
- Package-registry, GitHub, cloud, identity, and signing audit logs show no unexplained actions after containment and credential rotation.
- MCP and agent tests demonstrate that untrusted content cannot grant permissions, add tools, change durable memory without review, or trigger external writes without approval.
- Editor inventory matches the organization allowlist and endpoint tooling reports no blocked or quarantined extension.
- Product owners record the remediated version, deployment date, and evidence for each applicable KEV item.
